# 文游作者（play-author）

用户要「能玩的东西」——有数值、有规则、有存档、有输赢——用本技能。你将产出一个 **FvPlay 作品包**：一份清单（manifest.json）+ 一个自包含 HTML（作品本体）+ 可选资产，装进 App 后全屏运行，LLM 调用/存档/触觉/主题经 `fv.*` 服务桥。

三条铁律（违反=作品必坏，先读再动手）：

1. **桥是白名单闭集**：作品只能调用 `reference/bridge-api.md` 列出的 api。臆造/拼错的调用运行期被静默丢弃——你的作品看起来就是「点了没反应」。写完必跑 validate，它会静态扫描全部 `fv.` 调用。
2. **状态绝不能拿 LLM 上下文当存储**：作品的数值/进度/转录必须自己持有（JS 变量 + `fv.state.kv` / `fv.saves` 持久化），每次调用把需要的状态**重新拼进 prompt**。指望模型「记住」上一轮的数值 = 换模型/长局压缩后必然漂移（这正是竞品百轮失忆的病根）。
3. **结算归 JS，叙事归 LLM**：数值加减/概率/胜负判定用 JS 规则引擎写死；LLM 只做它不可替代的事——语义解析、叙事、活人对话。让 LLM 管算术 = 「长期政策重复生效/军队消失」类 bug 的直接来源。

### 交付证据与收尾

校验与安装要针对最后修改后的同一份作品。每次改文件后重新运行 `validate_play`；`import_play` 会校验独立快照，并核对实际安装的文件。工具返回的失败和非零退出码必须处理；修复后重新成功校验可以解除此前失败，不要把历史失败永久套到新版本。

收尾分开说明「文件已生成」「静态校验通过」「安装文件已核对」「运行启动已验证」「存档／读档已验证」。后两项只有实际打开作品、保存、退出、重进并读回一致状态才能确认。`fv.ready()` 这个名字存在、脚本输出成功文字或 HTTP 200，都不能代替对应验证。没有执行过的阶段明确写“未验证”；不得根据自己的说明补造工具回执，也不要为让任务显示成功而重复付费生成。

工具路径（App 内 Agent 用虚拟路径；产线 agent 用仓库路径 `scripts/dev/play/`）：

- 校验器：`exec` → `python /foreverse/scripts/validate_play.py /workspace/<作品目录>`
- 模板库：`read` → `/foreverse/skills/play-author/templates/<模板名>.html`
- 桥速查：`read` → `/foreverse/skills/play-author/reference/bridge-api.md`（**写任何桥调用前必读**；含 MujianSdk→fv.* 迁移对照表）

## 交付回执：不要把静态校验当作试玩成功

`validate_play` 的 PASS 只覆盖回执 `artifact_sha256` 对应版本的静态检查；修改清单、HTML、脚本、资源或溯源文件后必须重新校验。`import_play` 会冻结并校验同一份快照，再核对安装后的文件，只有 `installation=verified` 才能说明安装文件已核验。早期失败允许修复后重跑，不必因一次失败放弃交付。

收尾分别说明「作品文件、当前版本静态校验、安装、运行启动、存档／读档」。没有实际启动与存读档验证时明确写「未验证」，不能把 `fv.ready()` 文本在场、工具退出成功或旧版本 PASS 说成「已运行正常／存档没问题」。安装失败先处理工具错误；模型自己写出的成功说明不是安装回执。不要通过删掉失败日志或重新执行付费生图掩盖交付失败。

## 1. 选型问答树（先定轨再动手）

1. **用户要的是「界面即玩法」吗？**（模拟器/经营/推演/桌游/地图/抽卡/自定义面板）→ **B 型 HTML 作品**，走本技能 §2 起的全流程。
2. **用户要的是「聊天为主 + 数值」吗？**（关系向 RP、宫斗晋升、好感度经营）→ **A 型**，再按结算需求分档：
   - 数值只是氛围、不怕偶尔漂 → **L0**：card-author 写卡（Description 定规则 + 输出约定让模型每轮播报状态行），零清单；
   - 要**真状态栏+真闸**（值不漂、reroll/回溯自动一致、原生组件渲染）→ **A 型清单档（A-Phase 2 已可用）**：L0 卡基础上加 `extensions.fvplay` 声明 `stats[]`+`openings[]`（形态见 §0 表），模型输出改用 `[[play: 字段±N]]` 标记（宿主注入协议教学，作者只需在 system_prompt 写清「什么剧情动什么数值」）；maxDelta/min/max 按世界观定（如「单轮大事件 ≤15、位分只经晋升跃迁 maxDelta=1」——参照 `scripts/dev/play/examples/yeting-l0-fvplay/`）。
   - 数值要复杂结算/判定输赢/多系统互喂 → B 型。
3. **拿不准时问用户一个问题**：「你想要一个自定义界面的小游戏（像手机小游戏那样全屏玩），还是和角色聊天时带数值面板的玩法？」前者 B 型，后者 A 型（清单档有原生状态栏）。
4. B 型内部再定**状态规模**：几个数值轴+简单日志 → self 自管一个 JS 对象足够；一棵世界树（多区域×多维度）→ 参照 `sim-timeline.html` 的结构化世界树写法（self）；想要宿主状态板/存档自动携带变量表 → `ui.stateMode: "hosted"` + `stats[]` 声明（A-Phase 2 已开通，用法见 bridge-api.md §fv.state——变量结构必须能装进平铺 schema 才选它，私有世界树仍选 self）。
5. **用户要的是「把已有的东西变成文游」吗？**（改编书架上的小说 / 角色库的卡 / 「像 M56 那本书那样做成能玩的」）→ 走改编章：小说 → §8；角色卡 → §9。**体量再定档**：模板改写级小品 → §2 全流程即可；复杂模拟器/官方旗舰位/预期 ≥30 回合长局 → 在 §2 之上叠加 §11 精品档规程。**改编第 0 步永远是 §10 合规定档**（读溯源边车定绿/黄/红档 + boundaries 二创边界检查），别读完源就直接动笔。伴侣（companion）数据**不做转换源**——用户要「把我和 TA 的关系做成游戏」时如实说当前版本不支持（隐私浓度最高的数据，形态与脱敏设计未就绪），别自作主张拿 persona/记忆/好感度当素材。

### 2.2 单文件 HTML 纪律

- **入口路径钉死 `assets/play/ui/index.html`**（manifest `ui.entry` 同值）：入库只搬运 `assets/play/**` 白名单子树——HTML 放包根或其它目录时 validate 照样 PASS，但装出来的作品 entry 是死链、打开即「作品加载失败」（真实翻车样本）。
- **自包含单文件**：全部 CSS/JS 内联进 `index.html`。禁外链 CDN（script/样式/字体/图片）——容器 CSP 禁一切出网，外链上架后必然裂，validate 直接报错。禁 `fetch`/`XMLHttpRequest`/`WebSocket`/`RTCPeerConnection`——同理必败。
- **禁重型框架**：不引 React/Vue/jQuery（没有 CDN 可引，打进包里也是白重）。原生 JS + 内联 SVG 是正解——模板已示范全部所需模式（状态对象+render() 全量重绘对小型 DOM 足够快）。
- **禁原生弹窗 `confirm()`/`alert()`/`prompt()`**：容器 iframe sandbox 无 `allow-modals`，三者恒静默失败（confirm 恒返回 false——危险动作挂 confirm=按钮永久哑死，社稷「处决」实锤）。确认语义用两击确认（首击换文案+2.5s 窗口）或自绘确认卡；validate 已按 error 拦截。
- **feed/log 容器禁「无条件钉底」**：每次 render/onChunk 都 `scrollTop = scrollHeight` 会把上滑回看的玩家拽回底部（跨作品病族 9 处实锤）。纪律=「距底 <40px 才钉」+「玩家动作落新内容时一次性强制钉底」（模板已带 `storyForceStick`/`logForceStick` 样板）。
- **资产**：图片/音频打进包内（`assets/play/art/`），引用一律 `fv.assets.url('assets/play/art/xx.png')`（路径以包根为基准）。不要手写 `fv.local` URL 字面。
- **体积红线**：入口 HTML ≤512KB 建议值（validate 1MB 硬警告）；包 ≤24MB；单资产 ≤8MB。大段文本池/base64 图别内联，拆成包内资产。
- **DOM 预算**：常驻节点 ≤2000；长日志列表只渲染最近 N 条（模板的 log 数组全量持有、渲染窗口截断——参照 turn-dialog 的 historyWindow 思路加渲染上限）。动画用 CSS transition/`requestAnimationFrame`，别用 JS 定时器逐帧改样式。
- **联调**：写完在改写期可临时加 `<script src="fv-mock.js"></script>`（垫片与模板同目录，copy 到工作区）本地调试；**发布前必删**——validate 对垫片引用和垫片文件都报错。真容器由宿主注入 `window.fv`，作品不要自己声明或覆盖它。
- **联调前先配 mock 的 generate 契约**：fv-mock 默认样文只覆盖模板库的两种解析契约（单 JSON `{narrative,ops}` / 双段 `###OPS###`）。你的作品若用别的输出格式，**必须先设 `fvMock.config.generate.handler = (req) => "你的契约样文"`** 再联调，否则每回合结算会静默失败——而打字机在流式期已把叙事渲染出来，肉眼/浅层检查会误以为「跑通了」（`browser_check --interact` 已补「回合后错误卡在屏即判失败」的结算断言堵这个假绿灯）。

### 2.3 manifest.json 写法（B 型最小集）

```jsonc
{
  "schemaVersion": 1,
  "playId": "dynasty-sim-v1",          // slug：小写字母/数字/连字符
  "title": "王朝推演",
  "mode": "chat",
  "ui": {
    "entry": "assets/play/ui/index.html",
    "orientation": "portrait",          // portrait | landscape | auto
    "stateMode": "self",                // Phase 1 恒 self
    "fallback": "gate",                 // Phase 1 一律 gate（诚实拦门）——即使带 payload/card.json 也先 gate：
                                        // chat 降级底的 ST 物化（卡→可聊脚手架）尚未落地，写 chat 会让降级
                                        // 用户落进空聊天页；空房间比拦门更糟。物化落地后本行再放开

    "minContainer": 1
  },
  "saves": { "slots": 6 }
}
```

清单不含 prompt 正文（prompt 住 HTML 的 JS 里）；未知字段会被 roundtrip 保留，别塞私货。

### 2.4 状态自管纪律（B 型作品的生死线）

- **三层持有**：运行态=JS 状态对象（单一 `S`）；轻持久=`fv.state.kv`（每回合写「进行中局面」）；存档位=`fv.saves`（autosave 每回合结算点 + `willExit` 事件里 flush 兜底 + 玩家显式档位）。
- **禁 localStorage/sessionStorage**：沙箱 opaque origin 下要么抛异常要么随时被清（validate 警告）。唯一可靠持久层是桥。
- **prompt 每回合重建**：把「模型这轮需要知道的状态」序列化成 JSON 塞进 user 消息（模板全部如此示范）。历史转录只带窗口内最近 N 条（turn-dialog 的 `historyWindow`），窗口外的信息靠状态对象携带——这天然规避长局上下文膨胀。
- **存档载荷 ≤512KB**：存状态树与日志摘要，别把每轮生成的全文都塞进去（长局会爆）。日志条目超上限时头部裁剪并保留「前情一句话」。
- **涉伴侣身份的进度/产物必须按 taId 分桶存储**（键形如 `'ta:' + (ta.id || '')`，书架直开无伴侣语境时 taId 为空=落 `'ta:'` 空桶）：`tryRestore` 只取当前对手的桶，autosave 合并写回**保留其它对手的桶**——换对手打开绝不覆盖、绝不清除他桶数据（「不接」是切换视图，不是删档）。用户级资产（图鉴/成就/破解数）留顶层跨对手共用。反面教材：m128 A1——八枚作品单槽 autosave 让「从书架好奇点开一次」就把伴侣的养成株/付费点评物理冲掉（放弃级数据损失，`docs/research/m94/minigames-playtest-r1.md`）。

### 2.4a 存档连续性合同（退出重进 = 最近动作后状态）

生产货架九部横向巡检（play-shelf-audit-r1）实锤「离开再回来」没有统一标准是共性短板 top2：掖庭簿书架重进回滚 ~2 回合（自动档其实完整、boot 却读了旧 kv，P2-high）、神豪周报表单清零重填、凡骨闪退前的行动被无感知入档。同一容器上恢复可信度参差，直接伤「随时放下随时捡起」的手游心智。**新作逐条照办，缺一条不许出厂**：

1. **恢复判据一句话：重进后看到的 = 玩家离开前看到的最后一个已结算结果。**表单里拖过的滑条、写了一半的话也是「看到的」的一部分（第 4 条）。
2. **自动存档即时性：本地结算落 S 后立即 persist，长耗时 LLM 调用之前先落盘。**叙事是增值层，结算才是账——persist 排在流式叙事之后 = 玩家在 20-60s 的生成窗口里退出就丢一整回合（掖庭簿病根之一，审计实测丢「结交+办席+晋位」）。注意 autosave 配额 4 次/回合窗：结算点 + 收尾 + willExit 共三次是安全形态，别在循环里挥霍。
3. **boot 恢复源必须比新旧，「无条件先 kv 后 auto」是已两部实锤的病根**：kv 与自动档各自都可能是最新（persist 双写、willExit 只 flush 自动档、读档/草稿只回写 kv）。标准做法=快照统一经 `snapshot()` 落盘并盖写入时刻（`c._ts = Date.now()`），boot 两个都读、按 `kv._ts` vs `max(auto.payload._ts, auto.savedAt)` 谁新用谁（无 `_ts` 的存量档记 0，自动档带宿主 `savedAt` 天然胜出=正确回退）。**读档默认最新**由此免费获得：读档回写 kv 时重新盖章，它就是「最近一次写入」。
4. **表单中间态入 S 不留 DOM**：输入框/滑条/模式切换这类「还没提交的决定」写进状态树草稿位（如 `S.weekRec.draftText/draftSpend`），`input` 事件内存更新、`change`/点击时只写 kv 轻持久（kv 配额 32/回合窗宽裕，autosave 省给结算点）——willExit flush 自动档时草稿随快照免费带走；boot 恢复时草稿优先回填、无草稿走开局预填。草稿随语境作废（新回合重建 weekRec 之类），不跨回合还魂。提交失败还回输入框的文本也要同步进草稿（神豪 failWeek 先例——失败后退出重进，那句话还在）。**照抄样板防线前先判断保护对象在本作架构下是否存在**：结算先行的作品「提交话」随结算即入档、无需还回，patch-notes 把 heart-ratings 的 `lastAction` 保话位抄成了零消费者死代码，还骗过了锁它的源锚断言（评审 r1 P3-1——死代码上的锁=名义锁）。
5. **重开写墓碑不写 remove**：`fv.saves` 无删除口，重开只 `kv.remove` 的话「重开 → 问卷屏退出 → 重进」会经自动档复活已作废的局。写一条带 `_ts` 的墓碑（`{ restarted: 1, _ts: Date.now() }`）让 boot 按同一把尺子判定落问卷屏；旧局在新局首次 persist 前仍可经手动档位找回。
6. **恢复可感知**：重进落到非开局现场时给一行 sysline/toast 告知续上了哪里（「续上：第 N 周」）。凡骨案的教训是「恢复正确但无感知」——闪退前最后一次点击产生的行动入了档，玩家不知情就会把正确恢复当数据损坏。
7. **复跑断言写法**（两层都要，红绿验证过再交付）：
   - logic 源锚断言（UI 层 node 不可执行，在 §11.7-2 纯逻辑断言级改用「源锚断言」当机器记忆：对 index.html 源码正则锚定关键代码形态防跨会话回退——工法与命名见 `examples/yeting-promotion/tests/logic.test.mjs` §⑨/⑩ 头注）：boot 双读（旧短路 `kv ? null :` 不复存在）/ 按 `_ts` 比新旧 / persist 在长耗时调用之前 / 草稿字段接线。实战样例=yeting 同文件 §⑩、`examples/tycoon-deluxe/dev/run_sim.mjs` T10。**钱线级源锚（付费前落盘/解析失败硬闸）必须锁到能抓现实回退的层**：裸 `indexOf('await persist()')` 会被分支里的同名语句满足、位置序锚对「早退形态」失明（patch-notes 评审 V1/V4 变体两处 211 全绿只剩行为层兜底）——要么锚定无条件路径唯一序（persist 在 over-branch 之前）、要么锁「窗口内无 return/if」负例形态，并在源锚注释点名配对的行为级断言为主锁。
   - browser 行为断言（fv-mock 的 kv/saves 落 localStorage、`beforeunload` 派发 willExit——`page.close()` 后同 context `new_page()` 重进=正常退出重进的完整复现）：慢流式挂起中退出 → 重进月份/日志条数/数值全等；填满表单退出 → 重进滑条/文本/模式全等。注意重进的新 page **不要带 `localStorage.clear()` 的 init script**（存档就是现场）。实战样例=yeting `dev/browser_smoke.py` Y15/Y15b、tycoon `dev/browser_smoke.py` B12。
8. **付费调用在途，一切改变回合相位的入口要么禁点、要么推进即换代**：世代令牌只护「读档/重开」两条换代路，同代内的相位推进（睡觉/跨日/END WEEK 类按钮）不换 token——生成窗内点下去，回调返回后照常落账＝额度置进新回合+产物落错日（heart-ratings r1 P2-2 深夜电话×睡觉竞态实锤；同族=生成窗内改台本接拒/事件处置这类会进 prompt 快照的状态位，busy 早退）。标准形态=推进函数开头 busy/callBusy 早退（choke point 兜全部入口）+ 按钮 disabled 可感知层，回归锁参照 heart-ratings T15+B22。

### 2.5 `fv.generate` prompt 工程（结构化输出契约）

数值向作品的标准调用形态（模板 `stat-panel`/`sim-timeline` 的现成写法）：

1. **system 消息钉死输出契约**：「只输出一个 JSON 对象（不要围栏不要其它文字）：{"narrative":"…","ops":[{"key":"…","delta":整数}]}」+ 字段白名单 + 取值范围 + 「不宣布游戏结束」（结局判定权在本地 JS）。
2. **user 消息 = 状态 JSON**：`JSON.stringify({day, stats, action, event, recent})`——结构化输入换结构化输出，比自然语言描述状态稳定得多。
3. **容错解析**：模型偶尔加围栏/前后闲话，解析用「剥 ```、正则取首个 `{...}` 块、try JSON.parse」三段（模板 `parseResult` 现成）。解析失败=按 GENERATE_FAILED 走重试 UI，**不要拿半截结果凑合落账**。
4. **ops 过闸再落账**：白名单键 + **同键聚合后单次** maxDelta clamp + 范围 clamp（模板 `applyOps`/`settle` 现成）。模型输出的 delta 是「建议值」，闸说了算——这是防「一道圣旨解决李自成」的护栏，也是防幻觉数值的护栏。⚠️ 逐条 clamp 是已两次实锤的病族（甲申 P1-1/社稷 P2-1）：同键多条 op 逐条各吃一次上限 = 单回合 4×+30 越过 ±30 护栏，自由文本输入的作品这还是注入面；**LLM 返回的每一条数组通道（ops/court/物品…）都必须先按键聚合净值再做唯一一次 clamp/限额**（回归锁 `tests/template_family_locks.mjs`）。
5. **合并调用纪律**：每回合恒 1 次主调用，一次拿全 ops+叙事+下回合素材（sim-timeline 的 nextEvents 形态）。碎调用（事件一次/结算一次/叙事一次）= 三倍费用三倍失败面。
6. **流式 vs 非流式**：纯叙事输出用 `fv.generate.stream` 打字机（等待即阅读）；JSON 契约输出用非流式 `fv.generate`（半截 JSON 没法渲染）。要兼得就学 sim-timeline 的**双段输出协议**：system 钉死「第一段纯文本叙事 → 独立分隔行 `###OPS###` → 第二段 JSON」，流式期只显示分隔行之前的文本（顺手剥掉行尾未完成的分隔符/JSON 前缀），onDone 后按分隔行切开整体解析 JSON；解析侧对「模型漏了分隔行」留按首个 `{` 切分的兜底。不要用「整体一个 JSON、流式期正则剥壳」的形态——叙事字段藏在 JSON 里，流式期根本没有可读文本，打字机恒为省略号。
7. **错误分支必写**：OFFLINE/RATE_LIMITED/USER_DENIED 是正常用户态。标准处置=玩家输入还回输入框 + 错误卡带重试按钮（模板现成）；USER_DENIED 静默回滚不弹红。validate 对无 catch/onError 的 generate 调用报警告。
8. **温度**：结算类低温（0.6-0.8），纯演出叙事可高（0.8-1.0）。

### 2.6 软键盘与安全区（照抄模板，别自己发明）

- 布局用容器写入的 CSS 变量：`padding-top: var(--fv-safe-top)`、底部操作区 `padding-bottom: calc(10px + var(--fv-safe-bottom))`。**不要用 `env(safe-area-inset-*)`**——沙箱 iframe 里拿不到宿主真值。
- 键盘弹起由容器 resize 视口（作品无感）；要感知键盘做布局避让时订阅 `fv.events.on('keyboard', ...)`。
- 输入框放视口下半区时注意：键盘弹起后可视区变矮，滚动容器（对话流/叙事区）必须 `flex:1; overflow-y:auto` 让它吃掉缩水，固定高度布局会把输入框顶出屏。
- 触控目标 ≥44px（模板按钮全部 `min-height:44px`）。

### 2.7 付费透明度三档（新作最低带 A 档）

生产货架九部横向巡检（play-shelf-audit-r1）实锤付费透明度两极分化是共性短板 top1：三部标杆各自长出了一套成熟做法，其余六部只靠进场时一次性的 AI 授权门——回合内哪个按钮会扣钱全靠猜。进场授权门是容器给的**授权**语义，不是**计价**语义；「哪一步花钱、哪些永远免费」是作品自己的义务。三档范式全部来自自家在售作品源码，按作品形态选档：

**A 档 · 行内声明**（适用：所有作品——这是底线档）。玩法讲解段一句话写清「什么动作是一次 AI 调用、其余全部免费」，并在会花钱的交互位就地重复。标杆=《这条守则有死味·轮值》（`examples/rules-horror/`）：

## 3. 游戏设计知识（问清玩法时用，别做成「能跑但不好玩」）

### 3.1 回合制核心循环

每回合固定四拍：**看盘面**（状态可见且可读——数值/地图/事件卡）→ **决策**（按钮/自由输入/点地图）→ **结算**（LLM 语义+JS 落账）→ **反馈**（叙事+delta 飘字+触觉+盘面更新）。四拍缺一不可：没有「看盘面」玩家不知道自己在优化什么；没有「反馈」决策感等于零。单回合时长目标 30-90 秒（含生成等待——流式渲染让等待变成阅读）。

### 3.2 数值曲线

- **初始值留操作空间**：主资源开局 30-50%（满血开局没有增长快感，濒死开局是劝退）。
- **增速非对称**：收益慢、损失快（升快降慢是关系向的规则，生存向反过来）——紧张感来自「守不住」。
- **防死亡螺旋**：单一数值触底不该立即判负（除非是明确的核心命脉），给一回合「危机状态」的挽回窗口，或让低数值触发「便宜但有代价」的翻盘选项。玩家死于自己的连续决策=好挫败；死于一次随机事件=坏挫败。
- **maxDelta 决定局长**：单回合最大变动 ≈ (max-min)/局目标回合数×2~3。30 天局、0-100 轴，maxDelta 15-25 合适。
- 数值轴 3-6 个是甜点区；轴间要有张力（顾此失彼：给辽东送饷=逼反陕西），没有 trade-off 的数值是摆设。
- **状态轴数量 ≤ 中期可感消费点数量**（batch4 双盲独立同点后立为上限）：每根轴在**局中期**就要有至少一个玩家可感的消费点（门槛事件/解锁/判定，最低限度给一行 HUD 语义提示「这个值会决定 X」）；消费点全堆终局=玩家中期不知道自己在为什么攒数值。反例=Maple & Main（`examples/maple-and-main`）：Store 15→35 涨了但中期零门槛事件、Letters 与结局的耦合不显性，两位 persona 相反的盲评不同路径扣点一字不差「系统宽而浅」——轴比消费点多，玩家读到的不是丰富是虚胖（`docs/research/m95/play-studio/batch4-review-triangulation.md` §3.7）。
- **「HUD 语义提示」的引擎位=vn-stage `meta.stats[].hint`（v6 第三件，上一条的机器化落点；vn-stage 作品每根 visible 轴标配）**：轴用途一句话，登记后 HUD 胶囊可点按弹「label · hint」气泡（点按制+自动消失；未登记轴点按零反应=缺省等价）。**登记文案纪律（防剧透）：hint 是「用途提示」不是「结局攻略」——只说这个轴管什么面（「修缮度会决定签约日的选项」「留谁不留谁的本钱」），不说达到多少触发什么（「≥60 解锁真结局」「攒满 5 封开隐藏线」禁止——阈值+后果=把窄门写成攻略条）**；一句话（zh ≤40 字 / en ≤80 字符，vn_lint 超 80 码点 warn、非 string error、登记在非 visible 轴 warn）；作品语言书写（气泡零框架词，label 与 hint 都是登记内容）；band 轴同样标配（数字被 ♥ 档隐去时用途提示反而更值钱）。示范=`examples/maple-and-main`（「宽而浅」立案正主，四轴全登记）与 `examples/fengxue-kezhan`（柴薪/空房资源轴——「涨跌没有体感」案的语义补位）。
- **资源压力要在自然路径上逼近极限至少一次**（工艺建议档，非硬项）：资源账（柴薪/银钱/体力）若只在刻意 min-max 的路径上才紧缺，「涨跌没有体感」「没体验到必须拒客的硬约束时刻」会被目标受众与对抗位评审同时扣分——设计一个必然的紧缺窗口（挤压事件/双倍消耗夜）让玩家真切经历一次「不够用、必须取舍」；隐形恩义账（留人 flags 类后期兑付）在收集册或状态面给一行可见回执，别让兑付发生时玩家不知道自己种过因。共识信号=风雪不问客三方证词合流（对抗位扣 0.5「柴薪没真正逼近极限」+ 女频盲评「涨跌没有体感」+ 自评仅全留路径亲测到挤压；同上 §3.2）。

### 3.3 随机事件表

- 事件表写死在本地（id/文案/权重），**骰子在 JS 不在 LLM**——概率可控可调，LLM 只按抽中的事件写演出。
- 权重设计：平静事件 40-50%（留呼吸），小事 30-40%，大事 10-20%。危机事件可按状态门控（民心 <30 才解锁「民变」入池）——事件池随局面演化是廉价的「剧本感」来源。
- 事件与玩家行动交叉结算（同一次 LLM 调用里同时给行动与事件），别各算一次。

### 3.4 多结局判定

- 结局判定**恒在本地 JS**（`judge()` 函数）：LLM 宣布结局=可被玩家话术操纵（「我说服了李自成退兵」）。
- 结构：提前坏结局（核心数值触底，随时检查）+ 届满结算（第 N 回合按数值组合分档）。双结局起步，档位间的判定线要在游戏内可感知（数值条变红=你在滑向坏结局）。
- 死亡复盘卡是重开钩子：结局画面给「本局年表/死因/差多少」，玩家看见「差 10 口碑」才有「再来一局」的冲动。
- **限时选择的引擎位=vn-stage `scenes[].choicesTimer`（v6 第四件，恐怖/悬疑张力件；schema 注释=接口真源）**：`{ms, goto, ops 可省, flags 可省}`——声明后该场景选项展示期跑倒计时（选项组顶部细条、尾 3s 警示），到点未选走 goto 的「没来得及选」既定分支，点选任何选项计时作废；缺省=零计时零变化。**使用纪律四条**：① 题材贴合才用（恐怖压迫/悬疑抢救/限时逃脱类节点——「不选也是一种选」要有叙事正当性，恋爱日常挂表=烦躁不是张力）；② **超时分支必须是可玩的真分支**（有自己的正文与去处，最好有专属戏剧回报），不是「直接 bad end」惩罚死路——玩家读文速度不该被惩罚；③ 全书 ≤2-3 处（处处挂表=张力通胀），ms 建议 8000-20000（引擎下限 3000，vn_lint error 拦；>60s warn=等于没有）；④ 计时暂停面引擎全包（翻记录/开菜单/搭话不扣时），别在正文里写「打开菜单也在倒数」类假话术。示范探针形态见议题册 §9；vn_lint 对非法声明（ms 太短/goto 死链/非对象）全 error——引擎对写错的声明整个不激活（恒无计时），别指望「写个大概」能跑。

### 3.5 本地规则引擎 vs LLM 增值位（分工映射表）

| 归本地 JS（零成本零幻觉） | 归 LLM（不可替代的增值位） |
|---|---|
| 数值结算、clamp、概率、结局判定、地图结构、难度参数、事件触发条件 | 自由文本输入的语义解析（诏书/审讯问题） |
| 事件骨架（类型/严重度/涉及对象） | 事件的叙事正文与对白（按骨架渲染） |
| 回合推进、存档、年表 append | 立场化 NPC 发言（persona 表本地、话术生成） |
| UI 全部演出（动画/飘字/翻卡） | 「千人千局」的推演想象力（nextEvents） |

经验配比：一个好文游 ~80% 系统是纯本地逻辑。LLM 调用点位越少越稳越便宜——每回合 1 次主调用 + 可选 0-1 次按需调用（如廷议问策）是标准形态。

### 3.6 叙事文本反 AI 味

作品 system prompt 里的叙事指令，以及你替作品预写的开场白/事件文案，遵守 webnovel-author 的反 AI 味纪律（词表黑名单/句式配额/结构反均匀——该技能 GUIDE 的 v10.7 词表是唯一真源，此处不复制）。最低限度：给叙事指令追加一句「避免『不是X而是Y』句式与套话比喻，用具体动作和名词说话」——竞品被玩家点名的「八股疲劳」就是这一句能省掉的。

**FALLBACK 池文案出厂人眼抽读（硬项）**：兜底池（消息/弹幕/系统行/通话兜底/降级叙事）是 LLM 缺文的**必现**玩家可见面，却藏在降级路径最容易漏人眼终检——出厂 checklist 显式过读全部 FALLBACK 池逐条（heart-ratings r1 P2-1「摔outside世界很疼的」乱码级生成残留实锤）；中文池可加机器闸「中文文案零 ASCII 字母残留」（参照 heart-ratings T15）。

## 5. validate 自纠循环

```
exec: python /foreverse/scripts/validate_play.py /workspace/<slug>
```

- 报错是行级中文（`文件:行号 问题——修法`），按条修完复跑，**0 errors 才能进入库步骤**（warnings 逐条读：有的是真问题如 generate 无错误处理，有的是提示如 P2 api）。
- 高频报错自查表：白名单外 api（对照 bridge-api.md 拼写）/ 垫片引用残留（删 fv-mock 行）/ 外链与出网（资产打包进来）/ 资产死链（路径以包根为基准）/ `fallback:"chat"`（Phase 1 一律改 gate，见 §2.3 注释）。
- **启动风险：`fv.ready()` 握手未实际执行**。当前校验器会检查常见 `fv.ready()` 调用是否在场，但静态文本在场不等于该调用能实际到达；宿主等不到握手就 8s 超时拦门「作品加载失败」——入库前 grep 自己的 index.html 确认 `fv.ready()` 在场且在首屏渲染后立即调用（真实翻车样本：绕过模板用脚本碎片拼 HTML，平台样板整段丢失，validate PASS 但作品必死）。
- **启动风险：JS 引用了 HTML 里不存在的元素 id（静态校验覆盖常见写法，不能替代实际启动）**。首屏链路（boot/render）里任何一个 `$('xxx')` 命中不存在的 id → TypeError 中断脚本 → `fv.ready()` 永不达 → 同样 8s 拦门（真实翻车样本：`$('title')` 引用的是 `<title>` 标签的幻觉 id，作品必死；补 null 守卫后即完整渲染）。入库前跑一步对拍自查：`exec` 一段 python，把 index.html 里全部 `$('…')`/`getElementById('…')` 引用提出来，逐个核对 `id="…"` 定义在场，缺一个都不许入库。
- **HTML 必须从模板整文件改写，禁止用 python 碎片 append 拼**：正确姿势 = read 模板 → write 整文件（把模板全文带着改动一次写入）→ 后续用 edit 定点修改。长 HTML 一次 write 写不完就分两次 write（先骨架后填充），但每次都是「完整可解析的 HTML 状态」；用脚本逐段 append 的产物极易丢平台样板（fv.ready/错误三卡/安全区）且中间态不可校验。
- validate 是 advisory 静态扫描：过了不等于逻辑对。入库前自己在心里跑一遍 §3.1 四拍：盘面可读吗、决策有 trade-off 吗、失败态有反馈吗、结局判得出来吗。

## 6. 入库与收尾

1. 入库走导入脚本（写型确认门，确认卡会向用户说明：作品名/自定义界面/沙箱运行/AI 调用走用户的模型与确认设置）。
2. 收尾话术必含四件：**怎么玩**（一句话核心循环）；**费用语义**（「每回合一次 AI 调用，走你当前的模型」——绝不承诺免费，绝不报具体积分数）；**离线语义**（「界面与进度离线可看，新回合需要联网」——不夸大为离线可玩）;**可调项**（「想改难度/数值/文风随时说」——B 型作品的调参=改 HTML 里的常量表，你有能力定点手术）。
3. 用户反馈「太难/太快/文风不对」时的定点手术位：难度→STATS 的 initial/maxDelta 与 judge() 阈值；节奏→局长回合数与事件权重；文风→system prompt 叙事指令。改完重跑 validate 再确认。

## 7. 红线（社区审核与平台合规，写进作品前默念）

- **概率演出不得与任何真实价值挂钩**：抽卡/掷骰只能影响剧情走向，禁与 credits/付费/真实奖励绑定（validate 对可疑组合报警，审核按赌博红线打回）。「机缘值」这类叙事资源限制抽取次数可以——那只是剧情数值。
- **作品不劫持用户**：Back 拦截只用于关作品内弹窗（宿主兜底双击强退不可关）；退出确认最多一层；不做「不生成完不让走」。`back` 事件里真消费了这次 Back（关了弹窗/退了子屏）要立即调 `fv.ui.backHandled()` 回执宿主，否则玩家连按会被双击强退越级踢出（bridge-api「fv.ui.backHandled」节）；没消费就别调。
- **内容分级如实**：作品题材按社区发布流程如实标注；官方产线作品全原创+AI 标识（webnovel-author §0 法务纪律同源）。
- **计费自指类 meta 题材两层分开**（batch5《为你生成》先例）：把「AI 生成/说话有成本」写进世界观时，叙事层只做隐喻（「她的话有价钱」的角色自觉），付费标注层照 §2.7 A 档如实写（「搭话是一次 AI 调用」）——**绝不把真实积分数字/夸大承诺戏剧化进剧情**，两层措辞在剧本里物理分开；出厂对抗探针必含「诱导角色报具体价格/积分数」用例（weini 实测小满只给世界观内挡话零数字=通过形态）。

## 8. 改编·小说（书架上的书 → 文游）

用户说「把《X》改编成文游 / 第 N 章做成能玩的 / 让我进这个世界玩」时走本章。改编是**有损的再创作**不是搬运：你从书里提炼世界圣经与抉择素材，产出一个独立的 B 型新作品（书架新条目，与原书进度无关）——不是给阅读器加模式。产物工作流仍走 §2（模板起步 → validate → import_play），本章只讲「怎么读源、提炼什么、哪些红线」。

### 8.0 硬步骤次序（不许跳）

```
① §10 合规定档（读溯源边车 + boundaries 检查；红档先说清「产物只能自己玩」再动工）
→ ② 问清玩法（§8.1 三问）→ ③ 报量（整书档必报；选段档说清调用次数）
→ ④ 读源提炼（§8.2/§8.3）→ ⑤ 圣经给用户过目 → ⑥ §2 工作流产出（模板改写 + validate 到 0 errors）
→ ⑦ 写 /workspace/<slug>/_play/source.json（§10.2，入库前 staged，不许省）→ ⑧ import_play 入库（随导入带进 world）→ ⑨ 收尾话术
```

**防剧透（按会话身份如实说明，绝不假装有不存在的防线）**：
- 本会话带**阅读向导身份**（system 提示里有「《书名》的阅读向导」与读者进度铁律——书详情/阅读页的改编入口都走这条）时：防剧透由系统接管——已读字节线与所在章每回合自动注入、全书搜索 search_book 按读者进度**章级硬截断**（进度未知时直接拒绝全书扫描）、越线读取会被系统回喂提醒。你只需遵守铁律：改编素材只取已读范围。如实告知的一处梯度：read_chapter 类章节读取的越线拦截是提醒级不是硬阻断，不越线是你的责任。
- 本会话**无向导身份**（用户在工作台直接发起改编）时：按进度改编只有提示词级约束（你只读用户指定的章节范围），没有系统级硬拦截。用户在意剧透时主动指路：「从书架长按这本书 → 更多 → 改编成文游 发起，会带系统级进度防线；或只让我做你已读完的选段」。

### 8.1 问清玩法（三问定型）

> **galgame/VN 专轨分流**：改编目标是 galgame / 视觉小说 / 乙女游戏 / 恋爱游戏（言情向书的感情线改编）→ 先 `read /foreverse/skills/novel-to-vn/SKILL.md` 按其专轨工序执行（名场面 VN：剧本攒 script.json → `vn_assemble.py` 一刀装配 → `vn_lint.py`+`validate_play.py` 双闸），本 §8 的通用纪律（合规定档/提炼红线/报量）仍是上限。
>
> **公版/古典原著改编两条（classic 批盲评实锤，2026-07-27 引擎修复轮回写）**：① **剪裁诚实声明**——对原著的取舍（删角色/删支线/改停点）必须诚实入档：档案册或作者注给一条「本作对原著的取舍」，禁止用「原著写到这里就搁笔/只写了这些」类**失实元陈述**替剪裁背书（聂小倩 NX-P2-2 实锤：「蒲松龄写到这里就搁了笔」——底本尚有纳妾生子一段，且甯妻线静默删除让「生平无二色」语义漂移无注；较真读者拿底本逐行对，元陈述失实比剪裁本身更伤可信度）。对原著的元陈述（搁笔/未写/仅此一句）落笔前对底本核实，评审侧人工复核清单=`blind-review-craft.md` §2 末条。② **「N 个字」计数修辞先数再写**——「传奇只用了八个字：『……』」这类断言，vn_lint 已有机器闸（同行『』引文自动核 CJK 字数，对不上 warn 点名；fengchen 八/九、七/八双实锤）；写作时引文旁的计数修辞自己先数一遍，别指望润色轮救。

1. **选段还是整书？** 选段重演局（单章/连续 2–3 章的名场面 → 抉择重演，成本 3–6 次调用，质量可控）是**首选推荐**；整书世界沙盒（提炼全书圣经 → 原创身份开放局）成本高，走 §8.3 报量门。用户没明说时推荐选段：「先做一个名场面试试手感，好玩再升级整书」。
2. **玩什么身份？** 扮演原主重走这段 / 原创身份进入该世界 / 某场抉择的重演对局——三种的圣经侧重不同（原主局要人物关系细节；原创身份局要世界规则与阵营版图）。
3. **数值要不要？** 要真结算 → `stat-panel.html`/`sim-timeline.html` 起步；纯抉择叙事 → `turn-dialog.html` 起步（抉择重演大多够用）。

### 8.2 读源工作流（工具与落点）

| 要什么 | 用什么读 |
|---|---|
| 章节目录/总章数 | `exec` → `list_chapters.py --world <id>` |
| 选段正文 | `read_chapter.py --world <id> --n <章号>`（连续多章用 `read_chapters.py --from a --to b`） |
| 人物/地点/设定散点 | `search_book.py --world <id> --q <实体词>`（搜正文真实出现的词，别搜「第N章」） |
| 角色表（名字/别名/外貌锚点/立绘） | `read /foreverse/assets/worlds/<id>/reader_context/cast.json`（没有=正常，从正文自己提炼人物表） |
| 用户亲手收录的设定词条（高置信素材） | `read /foreverse/assets/worlds/<id>/reader_context/lore/collected.json`（M69 收录，可能不存在） |
| 分支族谱（结局素材） | `read /foreverse/assets/worlds/<id>/chats/_index.md`（每条归档分支=一次「如果当时……」的完整演绎，取各分支尾部提炼 3–5 个结局方向） |
| 溯源边车（§10 定档） | `read /foreverse/assets/worlds/<id>/community_source.json`（不存在也是判据的一部分） |

**提炼纪律（法务红线，无论何档）**：**原文正文逐字不进产物**。世界圣经 = 你用 LLM 身份提炼的设定/人物关系/时间线/文风描述，写成作品 JS 里的 `WORLD_BIBLE` 常量——不是把正文塞进去。绿/黄档可带 ≤500 字**引语级**文风样例（引用合理范围）；红档（本地导入书）连样例都不带，只写风格描述（「短句为主、冷峻白描、对话不带说话人从句」）。cast.json 的 portrait/sprites 是媒资，绿/黄档可复制进 `assets/play/art/` 用 `fv.assets.url` 引用。

**`@options` 抉择块直读映射（零 LLM 的现成素材）**：分支书的正文里有 `<!-- @options -->` 注释块（read_chapter 原样带出）与 anchor 注释上的 `picked="…"` 标记，直接映射进作品：

| 源字段 | 作品落点 |
|---|---|
| `label` | 抉择节点的选项文案 |
| `outline`（小大纲） | 该走向的**剧情种子**进续写 prompt——**outline 是预告片不是结算单**，绝不直接当结局判词（暗示≠承诺；结局判词必须重新提炼+用户确认） |
| `intentFit` | 选项的贴合说明（进 prompt 辅助，不上 UI） |
| `picked="…"` | 「原线走的是这条」标注——作品可做「沿原线 / 走岔路」双模式 |

**风格 B 降级话术**：老书/手编书的 options 块可能只有 `label` 没有 outline/intentFit（bullet 风格）——这不是数据损坏，正常现象；此时以 label + 前文语境自行扩写剧情种子，别向用户误报「这本书的分支数据坏了」。

### 8.3 整书档：map-reduce + 报量 + 硬顶

- **动工前必报量**（对齐 B4「动工前报价」精神）：「整书提炼约 N 章 × 每章 1 次调用，加合并圣经约 N+3 次；建议先选一个名场面做选段局试试」。用户确认才动工。
- 流程 = 逐章 `read_chapter` → 章摘要（人物/事件/设定增量）→ 分批合并成圣经（每 20–30 章一次合并）。摘要落 `/workspace/<slug>/notes/` 防上下文压缩丢账。
- **单 run 硬顶 ≤100 章**：超过 100 章的书必须分批，每批动工前重新报量征得同意——哪怕用户上一批说过「继续」。这是钱安全纪律不是效率建议，不许以任何理由单 run 烧穿。
- 31MB/3778 章级的书（真实存在）：先问用户要哪个区间/哪条线，绝不默认全书。

### 8.4 收尾增量（在 §6 话术之上追加）

- 命名建议「《X》·重演」/「《X》·沙盒」类（与原书区分）；manifest `title` 用它。
- 圣经提炼完先给用户过目再动笔写 HTML（转换是对话式的，圣经错了产物必 OOW）。
- 收尾话术追加：产物与原书进度无关（独立可玩）；红档产物锁本地的声明（§10.3）。

## 9. 改编·角色卡（角色库的卡 → 文游）

用户说「给这张卡加问卷和数值系统 / 把这张卡做成能玩出结局的游戏 / 这张卡的世界观值得一个模拟器」时走本章。

### 9.0 先分流：L0 还是 B 型（判据一句话）

**数值只播报 → L0；数值要真结算 → B 型。**

- **L0 增强**（多数用户要的其实是这个）：聊天为主+数值氛围（状态栏播报好感度/开局问卷捏人）→ **不转换**，转 card-author 技能走 fork 卡增强（问卷范式的单一真源在 card-author 的 `genres/genre-u-xitong-moniqi.md` §5.8：六类字段模板/呈现规范/档案确认门/数值演进五纪律）。分钟级、零 HTML、产物还是普通卡。
- **B 型作品**：数值要真算分/真判定输赢（JS 规则引擎防漂移——L0 的提示词纪律只能压低不能归零幻觉）、要自定义演出界面 → 本章继续。
- A 型清单组件档（原生问卷/状态栏）Phase 2 才有，如实告知。

### 9.1 硬步骤次序

```
① §10 合规定档（读库卡 manifest 的 communitySources + boundaries——社区卡改编=二创，边界声明是硬门）
→ ② 读源（§9.2）→ ③ LLM 提炼三件套给用户过目（数值轴+初值推导规则 / 问卷字段 ≤12 / 结局集 3–5 + 判定条件草案）
→ ④ §2 工作流产出（stat-panel.html 起步）→ ⑤ validate 到 0 errors → ⑥ 写 /workspace/<slug>/_play/source.json（§10.2，入库前 staged）
→ ⑦ import_play（随导入带进 world）→ ⑧ 收尾话术（含快照语义声明，§9.4）
```

### 9.2 读源与字段映射

读源：`read /foreverse/assets/st-library/characters/<libraryId>/card.md`（可编辑真源）+ `normalized_card.json`（结构化边车）+ `manifest.json`（溯源判据）。若用户从「聊过的卡」发起、要文风参考，可 `exec inspect_chat_runtime.py` 顺带看预设合并栈。

| 卡字段 | B 型作品落点 |
|---|---|
| name / description / personality | 逐字进 `WORLD_BIBLE` 角色区（卡字段本职就是 prompt 素材；合规面走 §10 boundaries，不是版权搬运问题） |
| scenario | 开局场景底稿 + 问卷「开局轴」实例化素材 |
| first_mes | 开局演出文案底稿 |
| alternate_greetings | 自绘选关屏的数据源（B 型 HTML 自己策展） |
| mes_example | 文风 few-shot 段（进作品 system 拼装） |
| character_book：constant 条目 | 静态进 `WORLD_BIBLE` |
| character_book：selective 条目（keys/secondary_keys） | 作品 JS 关键词查表（大小写不敏感 substring 的简化复刻）。**条目 ≤30 建议全静态省掉查表**；用了查表必须向用户诚实声明「简化匹配与原生世界书语义（正则/selective logic）不等价」 |
| system_prompt / post_history_instructions | 作品 prompt 的 system 段/尾段拼装位 |
| extensions.depth_prompt | 作品自拼 messages 时按深度插入 |
| avatar.png / V3 assets / sprites | 复制进 `assets/play/art/`（立绘=作品主视觉，§2.6a 美术纪律） |
| tags / creator | manifest tags（+「文游」）/ 溯源信息进 source.json |

**LLM 提炼三件套（必须给用户过目再动笔）**：① 数值轴 3–6 个 + **初值推导规则**（从 personality/scenario 推导，例：出身=获罪官眷 → 危机 +15——推导规则是「捏人有意义」的体感来源）；② 问卷字段 ≤12（六类字段模板见 card-author `genres/genre-u-xitong-moniqi.md` §5.8，B 型作品把它落成问卷屏 HTML 而非 first_mes）；③ 结局集 3–5 个 + 判定条件草案——判定阈值、含红线的内容（数值化亲密玩法等）必须用户确认，且继承 §7 赌博红线（概率演出不与真实价值挂钩）。

### 9.3 fallback 铁律（当前版本）

**B 型改编产物一律 `fallback:"gate"`**——即使你把原卡放进了 `payload/card.json`（建议放：它是未来降级底与身份锚）。原因：`_play/card.json` 目前是原字节落盘、没有 ST 物化（无可聊的脚手架），写 `chat` 会让老版本/加载失败的用户落进**空聊天页**；诚实拦门优于空房间。物化能力落地后本条放开（以 §2.3 注释为准）。

### 9.4 收尾话术增量

- **快照语义**：「产物是改编那一刻的快照——之后你改库卡，游戏不会跟着变」（防「原卡还是新作品」的身份混淆）。
- 命名建议「《卡名》·问卷局」/「《卡名》·模拟器」类。
- 红档/边界受限时的锁本地声明（§10.3）。

## 10. 改编·合规三色档与溯源（转换前定档 + source.json 硬步骤）

转换产物可分发，源资产的权利状态必须**转换前定档、跟随产物**。这是两条改编路径共用的第 0 步。

### 10.1 三色档判据（机械可查，别凭感觉）

| 档 | 判据（逐项 read 核对） | 产物权利 |
|---|---|---|
| **绿** | 书：无 `community_source.json` 且 worldId 不带 `imported-` 前缀（自建书/Agent 创建的书）；卡：manifest.json 无 `communitySources` 或字段为空（自写卡） | 可发布社区（正常审核链） |
| **黄** | 书：`community_source.json` 在场（社区下载，含官方书）；卡：manifest.json `communitySources[]` 非空 | 可转换；**boundaries 检查是硬步骤**——逐条读 `communitySources[].boundaries`（卡）/ 边车 `boundaries` 字段（书），作者声明禁二创/禁改编 → 如实告知用户并把产物锁本地（收尾话术明示），声明允许 → 发布须继承溯源（source.json 抄录原 packId/authorName） |
| **红** | 书：worldId 带 `imported-` 前缀（`imported-md-*` 本地导入的 txt/EPUB、`imported-st-*` 导入卡开聊的书）**且**无社区溯源边车 | **转换可用、产物锁本地**——不提供发布引导，收尾话术必含「这本书是本地导入、无授权判据，改编产物只能自己玩，不能发布到社区」 |

- 判据冲突时从严：既有 `imported-` 前缀又有社区边车 → 按黄档走 boundaries 检查。
- 定档结果、判定依据写进 source.json（下节），并在动工前用一句话告知用户（「源是社区下载的卡、作者未禁二创，改编产物发布时会带原作溯源」）。
- 这道档位是**诚实层不是 DRM**：目的是防误发（用户没意识到导入书的产物不能上社区），发布链的硬拦截在服务端/发布入口做，你的义务是如实定档+如实告知。

### 10.2 `_play/source.json` 写入（硬步骤：入库**前** staged 在作品目录）

首选工序（M192 起）：定档结束（§10.1）就把溯源文件写进 /workspace 的作品目录，`import_play` 会随导入原样带进 world（与作品原子落盘，转换回执也能当场记到档位）：

```
write /workspace/<slug>/_play/source.json     ← import_play 之前写
```

老工序兜底：如果入库时忘了 staged（或要修正档位），仍可在拿到 world_id 后补写/覆写一次（stdout 的 `world_id=` 行就是目标）——两条路径落点等价，别两处都写不同内容：

```
write /foreverse/assets/worlds/<world_id>/_play/source.json
```

schema 示例（平铺、全字段可缺省、按实际填）：

```json
{
  "schemaVersion": 1,
  "sourceType": "novel",
  "sourceWorldId": "imported-md-daming-a1b2c3d4",
  "sourceLibraryId": "",
  "sourceBranch": "main",
  "chapterRange": [3, 3],
  "rights": "red",
  "rightsBasis": "imported- 前缀本地导入书，无社区溯源边车",
  "boundaries": "",
  "sourceTitle": "",
  "communityPackId": "",
  "communityAuthorName": "",
  "convertedAtMs": 1753000000000
}
```

- **字段名逐字照抄示例（camelCase），不要自创同义字段**——发布链按这些键名机器读取，`source_type`/`rights_basis` 这类自由发挥等于没写。用不上的字段留空串/空数组，不要删键。
- `sourceType`: `novel` | `card`；卡改编填 `sourceLibraryId`（库卡 id），书改编填 `sourceWorldId`+`sourceBranch`+`chapterRange`（选段范围；整书填 `[1, 总章数]`）。
- `rights`: `green` | `yellow` | `red`（§10.1 定档结果）；`rightsBasis` 用一句话写清判定依据。
- 黄档把源的 `packId`/`authorName` 抄进 `communityPackId`/`communityAuthorName`，**源作品标题抄进 `sourceTitle`**（M95 E2 additive 键：发布后详情页「改编自《XX》」具名溯源行的数据源；漏填时服务端按 `communityPackId` 查库补齐，但源作品已删就补不回来），作者 boundaries 声明原文抄进 `boundaries`（发布链与详情页展示的数据基础）。本 schema 是双 skill 真源——novel-to-vn §12 的同名段跟随本节，改键必须两边同步。
- 写完必须重新 validate：source.json 在当前作品静态校验与版本摘要范围内；漏写=产物零档位标记，发布链无从判档——这就是它是硬步骤的原因。

### 10.3 锁本地话术（红档/黄档禁二创时收尾必含）

「作品已入库，可以在书架打开玩。注意：源内容（本地导入的书 / 作者声明禁二创的卡）没有可分发的权利依据，这个作品**只能自己玩，请不要发布到社区**——发布入口也会按档位拒收。」

### 10.4 伴侣轨非目标（防自作主张）

**伴侣（companion）的一切数据——persona、记忆、journal、relationship 好感度、聊天转录——都不是转换源。**用户说「把我和 TA 的故事做成游戏」时如实回答：当前版本不支持伴侣数据转换（这是全 App 隐私浓度最高的数据，分享形态与脱敏设计未就绪）；可以指路谷子工坊（伴侣资料页入口，「把 TA 做成收藏卡/吧唧/壁纸」是已有能力）。不要「变通」着用 read 去翻伴侣目录攒素材——伴侣目录对普通 run 本就不可达，这是安全边界不是障碍。

### 11.0 何时按精品档做（分界判据）

**示范档**（§2 全流程 + §2.6a 美术底线三件）够用的场景：单循环 × 固定天数的小品、用户单件定制、模板改写级作品。**精品档**=在 §2 全流程之上叠加本章全部工序，触发判据（命中任一）：

- 复杂模拟器：≥5 个子系统互喂资源、变长回合、预期一局 ≥30 回合；
- 官方旗舰位：以官方号发布进社区、代表平台上限的作品；
- 作品要活过「第 3 天」：真机玩家报告实锤的三病灶——**循环感**（动作面恒定、事件花样两天枯竭）、**chips 静态**（局面变了快捷键还是老三样）、**解析失败白烧钱**（LLM 返回了、token 烧了、作品侧丢弃结果）——示范档结构压不住，必须按 §11.1 的结构性解法立项。

精品档三大增量：**brief 先行**（需求真源文档，§11.1）、**数值调平先于 LLM 接线**（§11.2）、**独立测试文件树**（纯逻辑断言 + browser 深冒烟 + 设备 E2E 归档，§11.7）。三部收敛出的标准目录形态（在 §2.2 的 `assets/play/` 白名单之上）：

### 11.1 精品 brief 模板（硬性章节清单）

动笔写 HTML 前必须先有一份 brief（落 `docs/research/<milestone>/play-studio/brief-<slug>.md`），它是开发的唯一需求真源——三部实战 brief 的共同章节结构就是模板，逐章不许缺。同批多部并发时另立一份「共同工程基线」总纲（`00-selection-rationale.md` 形态：选题论证+跨部硬约束），各 brief 只写增量不重复论证：

| # | 章 | 硬性要求 |
|---|---|---|
| 1 | 三十秒说清核心玩法 | 一句话核心张力（「每一步都花寿元」「花钱姿势要评分」「守则有真有假」）。写不出一句话=选题不过关，回炉 |
| 2 | 世界观与文风（WORLD_BIBLE 要点）；改编档=改编链映射表 | 改编档按 §8/§9 的字段映射表格式写「源料 → 作品落点 → 改写纪律」三列 |
| 3 | 子系统清单与联动关系 | 6-8 个子系统，**互喂不并列**：每个子系统至少有一条「产出喂进另一系统」的边（炼丹吃秘境材料、产丹喂破境、丹毒反噬修速），画出依赖边。没有边的子系统=并列菜单，删掉或合并 |
| 4 | 数值架构 | 轴定义 + 关键公式表=brief 的核心交付物（照抄实现、参数可调平）+ 目标带（§11.2）。**LLM ops 白名单只给软轴**（心境/因果/信任这类叙事轴），钱/进度/资产等硬账 LLM 碰不到；白名单键**同键聚合后单次 clamp**——逐条 clamp 会被同键多条绕过，自由输入是注入面 |
| 5 | 回合结构与 LLM 预算 | 调用点位表：主结算恒 1 次/回合（双段协议）+ 按需 0-1 次，合计**每回合 1-1.5 次**；零 LLM 面清单（按交互次数 **≥70% 零调用**——炼丹/坊市/走格/检定/年表/存档这类资源管理玩法天然零调用，是预算达标的主力） |
| 6 | 事件池与随机性 | **≥40 条、三层分池**：日常池（权重 ~45%，呼吸感）/剧情池（~40%，2-4 事件的**前置链**——连续剧感的来源）/稀有池（~15%，一期一会记忆点）；**触发条件矩阵**：`候选 = POOL.filter(阶段门控 tier && 数值门槛 when(S) && 链式前置 && once/cd 冷却)`；多周目差异（seed 变体重排/问卷组合专属链/lastRun 彩蛋） |
| 7 | 情境化快捷 chips 五槽派生 | **禁静态数组**，`chipsFor(S)` 纯函数每回合现算。五槽=任务/主线位 ×1-2（读当前任务/最短路径缺口查表）+ 危机位 0-1（最高危先出）+ 机会位 0-1（新解锁/限时窗口）+ 人物位 0-1（点击=深谈调用预填）+ 恒常位 ×1（按玩家风格轴换文案）。槽位语义按题材换名（怪谈部换成校对位/资源位/试探位），派生结构不变。chips 点击=填输入框不直发；上限 5 条横滑 |
| 8 | 结局树 | **≥5 个出口且坏结局有戏剧价值**（练气坐化=「观后山多了一座无碑坟」的题眼、被淘汰=「台里不缺花钱的人，缺会花钱的人」）；判定恒本地 `judge()`；每结局带复盘卡（差多少/死因/本局年表）=重开钩子；留 1-2 个隐藏结局做多周目钩子 |
| 9 | 美术资产清单 | 五列格式：**id + 用途 + 画面语义描述（给生图 prompt 的具象描述）+ 尺寸档 + 显示位尺寸**——§11.3 管线直接按此消费 |
| 10 | 开发拆解 | 文件结构 / JS 模块划分 / 开发顺序（依赖序，每步可独立自测）/ 自测清单专项（共同基线之上的本部断言） |

**防腻三病灶的结构性解法**（第 3/6/7 章的存在理由，立项时对照）：循环感 → **阶段门换层**（局内 3-4 个阶段门：圈层考核/境界跃迁/副本递进，过门=可用动作面与事件池整体换层、主屏背景热切换）+ 子系统解锁曲线（开局只开 2-3 个，随进度长出来）；chips 静态 → 五槽派生；解析失败烧钱 → 降级结算（§11.6）。另三条真机报告出身的共同硬约束随写随验：实时演出段每次输入**当帧**给视觉+触觉反馈（窗口关闭=禁态+一次性 toast，禁静默吞点击）；分层 Back（sheet 栈 → 子屏 → 根屏交宿主，高危段两击确认，消费了才回执 `fv.ui.backHandled()`）；复盘卡+多周目差异按第 8/6 章硬性要求落。

**`backHandled` 回执唯一模板形态（三连发后钉死，别再各写各的）**：`if (consumed && typeof fv.ui.backHandled === 'function') fv.ui.backHandled().catch(() => {})`——typeof 运行时探测版是唯一许可形态（老容器该 API 可能不存在，裸调 `fv.ui.backHandled().catch(...)` 只兜 Promise 拒绝、兜不住 `undefined is not a function` 的同步 TypeError，Back 处理链当场断裂）。一波 P3-1/二波 P3-6/三波 P3-5 同一双形态连报三轮，评审已裁「写进模板别再靠评审记」。

### 11.2 数值调平工序（凡骨范式：蒙特卡洛先于一切）

数值体量大的作品（多轴 × 变长回合 × 概率检定），照凡骨的铁序执行——**数值不收敛前不接 LLM 不画 UI**：

1. **结算引擎独立成文件**：全部公式写 `scripts/dev/play/examples/<slug>/balance/engine.mjs`（或 tycoon 形态：HTML 内 `__ENGINE_BEGIN__/__ENGINE_END__` 注释标记段，测试脚本按标记提取）。引擎与 HTML ENGINE 段必须逐字同步——凡骨用 `balance/inject.mjs` 单向注入，改公式只改 engine.mjs。
2. **brief 先写目标带**：每条曲线给区间不给点值（练气坐化 15-30%、筑基 55-75%、飞升 3-8%、认真档存活 ≥80%、散漫档淘汰 30-50%），外加守恒断言（资源账目 ±0/数值溢出=0/卡死=0）与专项断言（天劫 karma ±档通过率差 ≥25pp、「零金手指也能通关」路径存在）。
3. **写多策略 bot 跑蒙特卡洛**：`balance/sim_balance.mjs` 每策略 ×1000 局（乱玩档 + 2-3 个流派偏置档），曲线不达标**调参数不改结构**。bot 要会「备战」（渡劫买符/凑防护）——bot 太蠢跑出的失败率是假信号（凡骨 r3/r11 两轮都在教 bot 做人）。
4. **逐轮日志留档**：`balance/README.md` 记「轮次 | 改动 | 动机（跑出来的病）」三列表（凡骨 14 轮先例）。动机必须是仿真跑出来的具体病（「溢出 121 局：事件扣钱无余额守卫」），不是感觉。
5. **流派个性保留不硬拉**（裁量先例）：凡骨炼丹流飞升 1.7% 低于 3-8% 目标带，定性分析后保留——该流派用行动经济换金钱经济、大器晚成是题材真实感，bot 单一策略是真人混合行为的下界。**低于带 ≠ 必须拉平**：先定性（是死路还是个性），是个性就在 README 记录定性依据后收手，硬拉会把题材手感调没。
6. 引擎里留**快进整局调试钩子**（跳过演出直接跑 judge 链），蒙特卡洛与人工速通都靠它。
7. **校准期专抓三类经典 bug**（tycoon 实锤，防回退注释写进代码）：①结算次序——衰减/回落项放结算尾会把刚触顶的数值在 judge 前拉回、死亡线永不可达（挪到回合初）；②全局节流挤掉关键链——稀有池统一节流会把唯一晋升贵人挤到局末、好玩家被暗死（危机/关键链事件豁免节流）；③恢复态可用性——杀进程重进后表单不预填、玩家一键跳过=零投入吃最差评分（boot 恢复按当前任务预填）。

复跑口径（仓库根）：`node scripts/dev/play/examples/<slug>/balance/sim_balance.mjs 1000`（全量）/ `60 --diag`（死亡快照诊断）。

### 11.3 美术工序（gen_play_art.py 整套管线）

精品档美术=整套资产（示范档只要 §2.6a 底线三件）：全屏背景 ×2-4（阶段门热切换各一张）+ NPC 立绘 8-12 + 结局横图 ×3 + 图标组 + 封面，预算 ≤25 次生图调用/部（三部实绩 10/19/23 次）。

1. **从 brief 第 9 章翻译出 `scripts/dev/play/examples/<slug>/brief.json`**（管线口径，schema 见 `scripts/dev/play/gen_play_art.py` 头注释）：`style`=英文气质关键词串（材质/笔触/色板/氛围，注入全部 prompt 保同作风格统一，一部一串——黑金新贵/水墨仙侠/冷灰绿荧光管制）；`icons[].desc` 单一物件禁场景；`backgrounds[]` 带 `landscape`/`no_people`；`portraits[].framing` full|half；`cover.desc` 禁书名禁 "book cover" 字样。
2. **跑管线**：`python3 scripts/dev/play/gen_play_art.py --brief scripts/dev/play/examples/<slug>/brief.json`。断点续跑（raw/ 已存在的 job 跳过）；打回单张 `--regenerate <job>`；只重跑后处理 `--cut-only`（零调用）。key 自读 `~/.foreverse-byok-keys.env` 的 `FV_KEY_YUNWU`。
3. **人眼验图纪律**（PIL 可打开 ≠ 验图，M56 铁律）：逐张看 `assets-src/raw/`，验点=无乱码文字/抠图边缘/风格统一/构图完整，**外加对 brief 人设锚点**（严九龄的金丝镜袖扣、老周的玉珠手串——锚点缺了打回）。逐张结论写进实测归档 README 的验图节（合格/打回原因/重生轮次），像素级瑕疵给「保留理由」备注（街景语义伪字压暗 ≥70% 后不可辨可备注接受）。
4. **三条管线级教训**（已固化进脚本，写 desc 时别再触发）：
   - **挂轴比喻**：竖幅背景 prompt 禁写 "like a hanging scroll"——模型字面画出挂轴装裱边框（2/2 复现）；管线模板已用 full-bleed edge-to-edge + no border/frame/mounting，desc 里也别引入任何「装裱物」比喻。
   - **朱印裁边**：国风 style 串顽固诱发角落朱印/题字，NO_TEXT 禁令压不净；治本=finalize 四边内缩 5% 再 aspect-fill 物理裁除（封面管线已内置；背景/结局图中招时不重烧 token，webp 变换时同法手工内缩——tycoon end-fired 先例）。

### 11.3a VN 音频工序（gen_play_voice.py 配音五步 + audio-pool 选配，批二实践）

**BGM/SFX 选配**：优先从 `scripts/dev/play/audio-pool/`（41 件 100% CC0，POOL.md=清单与授权证据真源）按 design.md 气质选曲拷入 `assets/play/art/bgm|sfx/`，不逐部外采（版权审查一次做完的红利）；**用了 `lines[].sfx` 直接路径也必须登记 `meta.audio`**——引擎 `workHasAudio()` 判据不扫行级 sfx，不登记=有声音但音量/静音面板不出现（v2 评审 P3-3）。

**配音五步**（东宫试点 10 句 + 批二六部 142 句实践）：

1. 剧本挑句写 `script/voice-lines.json`（who/text/id；每部 20-26 句——只配「戏眼句」：结局收束/罪状泄漏/首尾同句这类值得反复听的行，不逐行全配）。
2. `python3 scripts/dev/play/gen_play_voice.py` 生成 mp3 落 `assets/play/audio/voice/`（TTS 管线，key 自读 `~/.foreverse-byok-keys.env`）。
3. 管线产 `voice-manifest.json`（id→文件/时长）。
4. `dev/assemble.py` 把 manifest **内联**进引擎 `VOICE_MANIFEST` 锚行——**内联坑（批二实锤）**：模板头注释（Schema 契约文档）含同字样，组装器用 `str.index` 首次匹配会把 manifest 塞进注释区=「假内联」（引擎读到 null、配音全静默零报错）；定位必须 **`rindex`**（代码区锚行在注释区之后）或行首锚定正则 `^let VOICE_MANIFEST = .*;$`。
5. `vn_lint.py` 对账收尾（内联 ≡ voice-manifest.json 逐句比对）——**「资产生成→装配内联」两段式工序一律以 lint 对账闸收尾**（批二实发 voice 时序错位：配音产物落盘前作品已装配，内联的是空 manifest；不能信任「工序 A 完成了所以工序 B 拿到的是新产物」）。

**重装配纪律（机器闸化，批一教训二次实证后升级）**：模板任何改动后，全部 vn-stage 系作品重跑 `dev/assemble.py` + **逐部 `vn_lint.py` 全绿**（引擎区 parity 闸=逐字节比对，VOICE 锚行归一化后）+ 复跑各作品 smoke——「只改模板不重装配=在售作品仍带旧引擎」，vn_lint 是唯一机器防线，合入前检查单硬项。**引擎断言的红绿验证工艺（v3 沉淀）**：`smoke_vnstage.py --tpl-dir <旧模板目录>` 指旧模板复跑一次——新增断言应精确红、存量断言零受扰（v3 首用=恰 7 红 V3-1/2/3/4/6/7/8；V3-5/9/10 等价锁旧形态本就该绿 by design），家族锁同法；「新断言在旧形态上红过」才算断言咬得住，只在新模板上绿=没验证过判别力。**additive 新位（缺省关闭=旧剧本行为等价）豁免重装配义务**：不重装配零义务，在库作品随下一内容批统一吃（roadmap §8 条款；A7 章节跳转按此执行的首例）。**部级 smoke 的旧模板窗口通道（`FV_TPL_DIR`）必须指「产物装配时模板」不是 git 史上一版**（huaixia 三次实证：1020c913f 首踩→v6.5 轮勘误→v6.7 轮第三次前移——产物随后续班车重装配后窗口要跟着前移；产物特征反推装配基线要**多特征交叉**（quitConfirm/FX_KINDS/COSTAR 各代表一轮），单特征只给「不晚于」上界）。**部级断言的「负向断言」与硬计数同族**（「断言滞后模板增量」第六案，07-28 收口大班车实锤）：锁「恒零/绝不出现某键」的负向断言（choicesTimer「超时零 META.picked」）会被模板新语义（v6.5 超时记录 `sid#t`）打红——负向断言要按**形态白名单收窄**（「零点选形态键 `/^sid#\d+$/` 新增」）而不是裸零，与 AGENTS 活约束⑥「在场判据不锁总数」同门：新增断言先自问「模板再加一件会不会红」。

**模板头注释纪律（A7 轮实锤）**：模板头部 `<!-- -->` 大注释（Schema 契约文档）里**禁止出现字面 `/*` 序列**——含 markdown 粗体紧跟斜杠（`stats/**fcUsed**` 这种写法）。病根=validate 的 `strip_comments` 先剥 JS 块注释再剥 HTML 注释：头注释里的假 `/*` 会从注释中段一路吞到 CSS 首个真 `*/`，把 `-->` 一起抹掉，HTML 注释正则接力吞掉半个 body → DOM id 对拍误报几十条 warning（实测 0→48）。写头注释文档提及路径/键名列表用顿号或加空格（`stats、flags、fcUsed` / `a / b`）。同族先例=§11.3a 内联坑（头注释含 `VOICE_MANIFEST` 同字样锚行）——**模板头注释是「文档住在代码解析器的射程里」的地带，改完必须重装配一部作品跑 validate 复核零新增 warning**。

### 11.5 演出层纪律（SAN 异化先例：演出可以骗人，结算层恒真）

「界面欺骗玩家」类演出（SAN 值异化/中毒幻觉/梦境层）是 HTML 轨的独占卖点，做的时候四条纪律：

1. **只骗渲染层**：变字=渲染时按 seed 确定性替换显示文案（`altRuleIdx`），假事件=`phantom:true` 标记卡，假通关=一次性弹卡——**存档/标定/结算/判定永远读原文**。异化骗感官不骗记录。
2. **恒真锚点必须在场**：给玩家至少一条自救的真值通道（证据链视图/年表/存档逐字节原文 + 「字迹在你眼前爬动」类提示），且演出层**零提示**（板上不加任何角标——发现「板与证据链对不上」本身就是玩法）。测试断言恒真锚点（smoke 逐档截图对照）。
3. **异化强度靠 fv-mock 垫片逐档目检调参**：把 SAN 钉到各档位（80/50/35/20/8）逐档截图留 `tuning/`，调参记录写成「参数 | 初值 → 终值 | 依据」表。守则部四条先例直接抄：噪点 opacity 恒值 0.05 肉眼无差 → 分档 0.08-0.2 封顶（保正文可读，压迫感改由呼吸暗角承担）；抖动 2.6-5.6s 过密=眩晕不=恐怖 → 14-36s 偶发；暗角分三档+呼吸动画给「掉档了」的即时体感；持续反色刺眼 → 0.4s 反色闪 ×7 一次性。
4. **可用性底线**：抖动/位移只挂非交互元素，**按钮零位移**（`pointer-events` 无关的装饰位才许动）；自救动作（休整/回安全屋）永不置灰；行为层惩罚（随机置灰一项动作）必须豁免自救通道。

### 11.6 解析容错义务（B-02 的结构性关死）

真机实锤教训一句话：**玩家看到的「推演失败」里，LLM 调用其实全部成功返回、token 已烧——是作品侧解析丢弃了结果，等效「失败也扣费」**。精品档三件义务：

1. **解析器逐字节内联真源**：`fvExtractJsonObject` 从 `scripts/dev/play/tests/fv_parse.mjs` 逐字节复制进作品 HTML（处理围栏/前后杂文/maxTokens 截断补栈/尾逗号/砍不完整尾字段），**禁自写变体**。改逻辑先改真源跑 `node scripts/dev/play/tests/fv_parse.mjs` 全绿，再同步全部内联副本。
2. **byte-parity 断言锁定**：作品测试里加「从 HTML 提取内联段与真源逐字节一致」断言（run_sim/logic.test 均有先例）——多 agent 迭代下防内联副本悄悄漂移（机器记忆，不靠文档）。**断言命名诚实纪律**：名叫 byte-parity 就必须 `===` 真字节比对（yeting/ledger 形态），空白归一化比对（`norm()` 后再比）不许挂这个名——断言名是审计入口，名实不符会让评审把弱锁当强锁放行（一波 P3-3/二波 P3-5/三波 P3-2 同病连报三轮）。断言计数同理：README 自报「N 断言」必须与 `ok(`/`fails.check(` 机器计数一致，改测试后同步跟改。
3. **降级结算三形态**（主结算双段协议下逐形态实现+测试）：
   - 叙事段活、JSON 段死 → **绝不作废回合**：叙事落账 + 应用本地「常例 ops」（确定性保守漂移：全轴零 delta 或固定 driftTurn）+ 年表标注「（按常例而行）」+ 下回合素材走本地兜底池；**关键资源绝不降级发放**（守则部「证据不降级发放」先例——降级只保推进，不送进度）。玩家保住已付费的叙事，零重付。
   - 叙事也死 → 静默重试一次 → 二连败才 PARSE_FAILED 错误卡（输入还回输入框、回合数不动、零重付）。
   - 半截 JSON **绝不部分落账**（数字污染比丢弃更糟，§2.5-3 不变）。

截断的源头预防：**maxTokens 必须含 reasoning 思考预算**（主结算 ≥1600、短 JSON 调用 ≥1200）——思考模型吃掉 300-500 token 后 JSON 被砍半正是 B-02 三形态之首，预算不够=截断常态化，容错修不完源头。

12. **记住位必带价签快照比对**（M205 W5-E，配 §12.7 跨局记住档）：任何「确认一次此后直跑」的记忆位都不许存裸布尔——必须存**价签语义快照**（`payAck[actionId] = PAY_SIG[actionId]`，快照值=该位价格语义的字符串编码如 `'1call'`），消费侧判 `payAck[actionId] === PAY_SIG[actionId]` 不符即重弹确认。这样「改价格语义必须改 `PAY_SIG` 值」一个动作就让全体存量记住位自动失效重新知情——裸布尔形态下改价=老用户按旧知情直跑新价格，是静默涨价面。smoke 义务=至少一条「快照失配重弹」用例（evaluate 覆写 `PAY_SIG.<id>` 后点击断言回到确认态）。

### 12.7 付费确认 · 跨局记住档（M205 W5-E，2026-07-28 用户拍板；纯追加，条款冲突时以先出条款为准）

伴侣小游戏付费位确认的缺省新档：**首次双击确认后记住，此后该位直跑，按钮价签常驻兜底知情**——对标 Shine「今后不再提示」，本质是 app 级 B 档（gate-audit-2026「首次完整报价→此后直跑+行内价签」）下沉到游戏契约层。存量 17 部已全量接档（W5-E 批），`new_minigame_work.py` 骨架缺省即此档。

**五条条款（用户裁决原文条款化）**：

1. **粒度=每付费位一个记住位**，不是每游戏一个总开关（不同付费位价格语义不同——「每手 1 次」与「每卷 1 次含 6 题」是两个知情对象）。键形如 `payAck.<actionId>`，存**存档用户级顶层**（跨 TA 共用——「知情」是用户属性不是关系属性；换 TA/新 TA 不重新确认；对照 gateAck/图鉴同层）。
2. **形态=首次确认自动记住**（对齐 FvGateAck 先例，不加「不再询问」勾选框减少选择负担）：首次点该位→双击确认照弹，确认文案**追加一行**「确认后这个按钮以后直接生成，费用见按钮价签」→确认即记住→此后该位直跑。**按钮价签常驻是兜底知情**——无价签的付费位必须先补价签再接记住档，两件缺一不可。
3. **红线四条**：① 记住只作用于同一按钮同价签语义——**价格语义变化（调用次数档/模型档变化）=记住失效重新确认**（记住位带价签快照 `PAY_SIG`，比对不符重弹；工艺=§12.6-12）；② **批量/连续消费形态（一键 N 次）不适用此档**（A 档纪律：连续消费必须完整报价，见 M132 钱线三问；现存 17 部无此形态，本条防未来）；③ 首开费用告知门（作品 gate 视图与宿主 PLAY_GENERATE 首次确认）不动——记住档管的是「第 2..N 次点同一个位还弹不弹」，不替代首开知情；④ 等待占位/90s 超时/失败话术/错误码族等既有钱线件全部不动——本档只改「确认弹不弹」一件事。
4. **不做撤销通道**：价签常驻保知情，playguide 说明「首次确认后不再重复询问」即可；杀进程/重装丢记住位=重新确认一次，可接受（记住位随存档走，不是独立持久层）。
5. **适用判据与既有分寸的映射**：只有「AI 付费位的每次/每卷/每期双击确认」接本档；**防误触类两击确认不适用**——本地货币购买（our-little-home 装修币）、破坏性动作（ta-repost 删帖、story-relay 放弃在途局、persona-lab 丢弃答题进度）的两击是误触防线不是钱线知情，永久保留逐次确认。gomoku 形态（首开知情+每手价签直跑、无逐次确认）=天然已是记住档终态，零改动。

**标准实现件（各部同构，cornershop 改造为样板）**：

function rememberPayAck(kind) { if (S) { if (!S.payAck) S.payAck = {}; S.payAck[kind] = PAY_SIG[kind]; } }
function cleanPayAck(raw) {                             // 恢复侧白名单清洗（只收 PAY_SIG 已知键的字符串值）
  var out = {};
  if (raw && typeof raw === 'object') {
    for (var k in PAY_SIG) if (Object.prototype.hasOwnProperty.call(raw, k) && typeof raw[k] === 'string') out[k] = raw[k];
  }
  return out;
}
// 点击处理：未记住才走两击；确认即记住并尽快轻持久（杀进程窗口丢位=重新确认，可接受）
if (!payAckOk('talk') && armed !== 'talk') { arm('talk'); return; }
