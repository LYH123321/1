# 小说改编 galgame（novel-to-vn）

用户想「玩」书架上的言情小说——重走名场面、在抉择点选原著没选的那条路、和立绘后面的角色搭话——用本技能。你将产出一个 **vn-stage 引擎的 FvPlay 作品**：名场面 VN（12±3 主场景节拍（§5）/ 2-3 结局 / 单角色感情线 / 5-10 分钟单周目），装进书架独立可玩，主线推进零 LLM 调用（断网照玩），只有 freechat 搭话走用户模型计费。

本技能是 play-author §8（改编·小说）的 **galgame 专轨特化**：合规三色档、source.json 溯源、提炼纪律等通用规程仍以 play-author §8/§10 为上限，本文只写 VN 专轨的差异工序。**不需要 read play-author 全文**——需要引用它的地方本文已浓缩，只有 §3 定档时按指引查判据表。

三条铁律（违反=白烧用户的钱或产出死作品，先读再动手）：

1. **全程禁止 read 模板** `/foreverse/skills/play-author/templates/vn-stage.html`（162KB≈10 万+ token，读一次烧穿预算），也**禁止手写 / 整写 / edit index.html 的引擎区与剧本区**。剧本只写 `/workspace/<slug>/script.json`（分幕 write --append 攒，§7），装配交给内置 `vn_assemble.py`（模板实例化/剧本注入/标题/垫片全自动，字节不过对话）；Schema 知识用本文 §8 浓缩卡。唯一允许碰 index.html 的例外=§7 末尾的可选主题色小 edit（装配后做，重跑装配不丢）。
2. **改编素材只取用户已读范围**。快速档「名场面 VN」的产品定义就是「把你读过的名场面做成游戏」，结局是「如果当时……」的原创演绎分岔，不是原著结局搬运。越线读取=剧透事故（§4）。
3. **原著台词逐字不进产物**。所有 lines[].text 必须改写（语序/用词/视角至少动其一）；红档（本地导入书）连引语样例都不带（§9 台词红线）。这是法务红线不是风格建议。

## 0. 分流：先确认这活该不该本技能接

| 用户说的是 | 走哪 |
|---|---|
| 「做成 galgame/视觉小说/乙女游戏/恋爱游戏」+ 书是**言情向**（现言/古言/穿书/重生/民国，有感情线主轴） | ✅ 本技能，往下走 |
| 同上但书是**悬疑/规则怪谈**（主轴是盘问/辨伪/生存不是感情线） | 如实告知：「悬疑盘问类的改编语法（线索轨/辨伪/死亡回溯）当前版本还没上，第二期会来。现在可以先按通用改编做成推演/探索局」→ 转 play-author §8 |
| 书是**男频玄幻/修仙/系统流/赘婿爽文**（主轴是数值成长/打脸，感情线稀薄） | 如实告知：「这本书的主轴是升级和爽点，做成 galgame 会两头不像——更适合做成模拟器/推演局（数值真结算那种）」→ 转 play-author §8 通用改编链，别硬套本技能产出低质产物 |
| 「把正文**演出来**/立绘演给我看/换个方式读这本书」 | 不是改编——指路阅读器内置 **VN 剧场**（阅读页开演出模式，零成本零改编，进出同一阅读进度）。一句话话术：「阅读器里自带 VN 剧场，把正文直接演出来不花钱；我做的是另一回事——把名场面改编成能玩出不同结局的游戏」 |
| 「把我和伴侣（TA）的故事做成游戏」 | 伴侣数据不是转换源（隐私红线，play-author §10.4），如实拒绝并指路谷子工坊 |

判断言情向拿不准时问一句：「这本书你最想『玩』的是哪段？是想改写某段感情的走向，还是想体验打怪升级？」前者接，后者转。

## 1. 工序总览（十步链，固定次序不许跳）

```
① 意图三问（§2）→ ② 合规定档（§3）→ ③ 已读范围侦察（§4，read_chapter ≤8 章硬顶）
→ ④ 改编蓝图过目（§5，唯一人工确认门）→ ⑤ manifest + 分幕攒写 script.json（§6/§7，write --append）
→ ⑥ vn_assemble 一刀装配（§7，自动实例化模板/写标题/删垫片/回读自证）→ ⑦（可选）主题色小 edit
→ ⑧ 机器闸自纠（§10，vn_lint → validate_play 双闸都免确认，≤3 轮）
→ ⑨ 写 source.json（staged 在作品目录）+ import_play 入库（§12）→ ⑩ 诚实收尾（§13，五件必说）
```

## 2. 意图三问（一轮问清，别拆多轮；全自动模式给默认值）

1. **「想玩谁的感情线？」**——默认=侦察后已读范围里对手戏出现频次最高的角色。
2. **「结局倾向？」**（甜/虐/开放）——默认=甜+虐双结局，好感够高解锁一个隐藏结局。
3. **「美术档？」**——报价必须在此步就给（动工前报价纪律）。**报价前先按 §11 的「素材库优先工序」查已导入的官方素材包**：命中的背景/BGM/SFX 在报价里报零成本复用，只报 miss 项的生图费用（例：「背景 6 张走《古风场景素材包》免费，只有主角立绘要生成 2 张 ≈2160」）。三档如实报：

| 档 | 内容 | 官方渠道价 | 话术要点 |
|---|---|---|---|
| **A 纯文字**（默认） | 零生图。引擎自带降级渲染：背景=渐变底+场景名水印，立绘=剪影卡（首字+名字+情绪徽标），完整可玩 | 0 | 「先做纯文字版试试手感，好玩再补立绘」 |
| B 封面+立绘 | 封面 1 张 + 主角立绘 1 张 | ≈2160 credits（2 张 ×1080） | 若书的 `reader_context/cast.json` 里已有该角色立绘，**零成本直接复制**，先查再报价 |
| C 全套 | 封面+2 角色 ×3 表情差分+背景 6-8 张 ≈15 张 | ≈16200 credits | **动工前一次报清总账**（张数 × 单价 ≈ 总价），并预告确认方式：「第一张图会弹一次付费确认，在那张卡上点『后续全部允许』就不用再逐张点了（想逐张把关就每张点应用）；中途随时可以停，已生成的图都保留」。执行纪律见 §11 |

BYOK 用户（自带 key）文字与生图都走自己的 key，credits 成本=0，报价话术换成「走你自己配置的模型，费用按你的 key 计」。

## 3. 合规定档（play-author §10.1 判据机械执行，零自由裁量）

动工前 `read /foreverse/assets/worlds/<worldId>/community_source.json`（不存在也是判据）+ 看 worldId 前缀：

- **红档**（worldId 带 `imported-` 前缀且无社区溯源边车——番茄导出 txt 的常态）：可以改编，动工前先说清：「这本书是本地导入的，没有授权判据，改出来的游戏**只能自己玩，不能发布到社区**（发布链有硬闸拦截）。想做能发布的版本，可以基于社区作品或官方小说发起改编」。用户接受再继续。
- **黄档**（有 `community_source.json`，社区下载含官方书）：读边车 `boundaries` 字段——作者声明禁二创 → 如实告知+产物锁本地；允许/未声明 → 可改编，**产物可发布**（带「改编自」溯源：发布时继承源作品 packId/作者署名，作品标 derivative）。官方小说与社区作品同待遇——官方书默认允许二创（2026-07-23 拍板）。
- **绿档**（自建书/agent 创建的书）：可改编，**产物可发布**。
- **发布口径（2026-07-23 拍板：发布口开放，App 发布入口已上线）**：绿档/黄档（无禁二创声明）产物可发布、红档锁本地——发布链按 source.json 的 rights 档位放行/拒收（App 打包预检 + 服务端主闸双侧同判据）。绿/黄档用户问「能发布吗」时指路真实入口：「可以发布——社区页 → 顶部『发布』→ 类型选『文游』→ 从书架选这个作品，走正常审核后上架」；**不要再对绿/黄档说「只能自己玩」**（那是红档专属话术）。红档作品在发布表单选中时会被当场拦下并解释原因。
- 判据冲突（既有 imported- 前缀又有社区边车）从严按黄档走 boundaries 检查。
- 用户自述「这本书是我自己写的」：不开自述通道，话术引导正路——「把作品先发布到社区（小说类型），再从社区那本发起改编，产物就带正规溯源了」。
- 产物台词是 AI 重写的演绎不是原文（§9 红线保证），用户担心「传播原著」时如实解释这一点。

## 4. 已读范围侦察（快速档形态，read_chapter ≤8 章硬顶）

**防剧透是产品定义不是约束**：素材窗口=已读范围 → 产物不可能剧透。三态如实执行：

- **书入口发起（会话带「《书名》的阅读向导」身份，主路径）**：系统级防线在场——search_book 按读者进度章级硬截断、进度未知拒绝全书扫描。你只需守铁律：素材只取已读范围。诚实梯度：read_chapter 的越线拦截是提醒级不是硬阻断，不越线是你的责任。
- **工作台直接发起（无向导身份）**：只有提示词级约束。用户在意剧透时主动指路：「从书架长按这本书 → 改编成文游 发起，会带系统级进度防线；或者告诉我你读到第几章，我只取那之前的内容」。
- **用户显式要「整本改编含原著结局」**：如实告知两件事——「会读到你没读过的内容，产物含剧透」+「整卷深度改编当前版本未开放（成本是名场面版的 5-8 倍），先做名场面版」。向导会话内做不了整本（硬截断挡着后文，这是防线不是 bug）。

**名场面窗口选定**（优先级从高到低）：

1. 用户点名的章节/场面；
2. `@options` 抉择块密度最高的窗口（分支书正文里的 `<!-- @options -->` 块=作者标注的戏剧张力点，read_chapter 原样带出；`picked="…"` 标注原线走向——直接吃进「沿原线/走岔路」双模式素材）；
3. `search_book.py --world <id> --q <目标角色名>` 命中密度最高的连续 5-8 章（**搜正文里真实出现的词**：人名/别名/称号，不要搜「第N章」）；
4. 默认=读者当前进度往回 5-8 章。

**精读预算**：`read_chapter.py --world <id> --n <章号>` **≤8 章硬顶**——这是钱安全纪律不是建议，不许自发全书扫描。窗口外的人物背景靠两份高置信补充材料（都可能不存在，不存在=正常）：

- `read /foreverse/assets/worlds/<id>/reader_context/cast.json`（角色表：别名/外貌锚点/立绘——有立绘则美术 B 档零成本）
- `read /foreverse/assets/worlds/<id>/reader_context/lore/collected.json`（用户亲手收录的设定词条）

## 5. 改编蓝图过目（工序唯一人工确认门，蓝图错=产物必崩，这一门省的返工远大于交互成本）

侦察完先产出 ≤2K 字蓝图给用户过目，**确认后才动笔**。五件套：

1. **人物卡草案**（2-3 人）：每人 persona（3-5 句：性格/说话方式/当前处境/与主角关系）+ style（台词风格一句话）+ fcTone（口吻纪律一句话）+ 拟用表情差分名（neutral 必有；纯文字档写 `{"neutral": "cast/<id>-neutral.png"}` 占位即可，引擎缺图自动走剪影降级）。
2. **场景节点表**（12±3 行=**主场景节拍数**，不是总场景数）：`场景 id | 一句话内容 | 好感变化 | 分岔点标注`。分岔变体场景（同一节拍按选择改写出的平行场景）不占节拍配额，但要有代价意识：总场景数（含变体+结局）**建议 ≤2× 节拍数、封顶 30**——变体是输出 token 的大头（宫斗书试转实锤：12 节拍拆出 37 节点，写作成本近翻倍），拿不准就少拆平行场景，用 flags+cond 在同一场景内做差分行。
3. **结局树**（2-3 个）：结局 id + 标题 + 判定条件草案（好感门槛+关键 flag）+ 一句话基调。
4. **名场面窗口声明**：「取材第 K–K+7 章，改编只到你读过的地方；结局是原创演绎的『如果当时……』，不是原著结局」。
5. **freechat 布点表**（3-5 处）：`场景 id | 一句话「此刻」锚点`——布在情绪余韵场景（纪律见 §9）。**这张表确认后要逐字抄进剧本 `meta.freechatPlan`**（§7 第一刀），vn_lint 会对账「蓝图声明 vs 实际布点」，声明了没做/做了没声明都会被点名（试点实锤：不列这张表，写着写着布点就丢了）。

用户改一条（如「结局倾向改虐」）就更新蓝图再过目。全自动审批模式下蓝图照常产出，改为「按这份蓝图继续做了，中途想改随时叫停」不硬等。

## 6. 工作区骨架（不需要也不允许自己搬模板——装配器会做）

`vn_assemble.py` 首跑会自动从模板实例化 index.html（并写作品标题、删联调垫片），你要准备的只有 manifest 和剧本（§7）。`<slug>`=小写字母/数字/连字符（如 `guifei-mingchangmian`）。

manifest 先写好（B 型最小集，`saves.slots` 钉 3=vn-stage 引擎手动槽数，配别的值会出幽灵槽位或存不进）：

```
write /workspace/<slug>/manifest.json
{
  "schemaVersion": 1,
  "playId": "<slug>",
  "title": "《原书名》·名场面重演",
  "mode": "chat",
  "imageSource": "ai_generated",
  "ui": { "entry": "assets/play/ui/index.html", "orientation": "portrait",
          "stateMode": "self", "fallback": "gate", "minContainer": 1 },
  "saves": { "slots": 3 }
}
```

## 7. 剧本攒写与一刀装配（防 token 爆的核心机制，逐字照做）

**为什么必须分幕攒写**：12-15 场景的剧本 ≈12-20K 汉字 ≈9-15K tokens，再加 hidden reasoning、JSON 结构和工具参数，即使普通 Agent 当前是 32768 的整体输出包络，一次生成仍容易在中途截断。分幕=每刀 4-5 个场景，正文输出 ≈2.5-4K tokens，给思考与工具调用留出余量。剧本全部攒进 **`/workspace/<slug>/script.json`**（纯数据文件，全程不碰 HTML——旧版「分幕 edit 注入 HTML+追加锚」工序已废除，锚错位/吃锚/漏刀整类缺陷随之消灭）。

**第一刀（write 建骨架：meta+characters+scenes 开括号）**：

```
write /workspace/<slug>/script.json：
{
  "meta": { ...你的真实 meta：title/slug/locale（剧本语言 "zh"/"en"，英文书必写 "en"，§8）/stats/endings/freechatPlan（蓝图布点表的场景 id 数组，§5-5 逐字抄）... },
  "characters": { ...你的真实人物卡... },
  "scenes": {
```

**中间 N 刀（write --append 追加场景，12-15 场景=3-4 刀）**：每刀 append 本幕 4-5 个场景成员+尾逗号：

```
    "s01": { ... },
    "s02": { ... },
    "s03": { ... },
```

**收尾刀（append 末幕+闭合）**：末幕最后一个场景成员**不带尾逗号**，随后闭合 scenes 与顶层：

```
    "s14": { ... }
  },
  "start": "s01"
}
```

六条纪律：① 文件终态必须是**严格 JSON**（双引号、无注释、最后一个成员后无尾逗号）——vn_assemble 会解析校验并按位置报错，报错就 edit script.json 定点修（script.json 是普通小文件，edit 随便用）；② append 可配 expected_length 防错序（每刀回执带字节数）；③ 场景 id 用 s01..sNN 顺号+结局场景 eXX，与蓝图节点表一一对应；④ `characters[].sprites` 路径**绝不留空串**——纯文字档也按 `cast/<id>-<mood>.png` 规范写（引擎缺图自动降级剪影、后补图零改剧本；写空串=之后生成的真立绘永远接不上，vn_lint 会 warn，试点实锤 B 档立绘白买）；⑤ **每个说话场景把在场角色写进 `scenes[].sprites`（谁在场谁上台，≤3 位）**——只写 lines[].who 不挂 sprites，引擎只显名牌不显立绘也不报错（v31《红楼梦·选回》实锤：三角色立绘齐活、全程空台），vn_lint 会按「有立绘表却整剧本零上台」warn 点名；画外音/CG 全屏特写的个别场景刻意空台是合法演出，不受影响；⑥ **不要自写 python 脚本去生成/合并/修补 script.json**——分幕 write --append 就是全部生成工序，坏了就 edit 定点修；gen_script/build_*/fix_json 这类自写生成器每一步都弹确认卡白耗轮次（英文书试转实测因此多烧 ~40% 调用），与 §10 的「不要自写校验脚本」同族同罪。

**一刀装配（免确认，字节不过对话）**：

```
exec: python /foreverse/scripts/vn_assemble.py /workspace/<slug>
```

它自动做四件事：首跑从模板实例化 index.html → `<title>` 写成 meta.title → **删除浏览器联调垫片**（旧工序的人工「垫片刀」自此消灭——试点实测这刀最容易漏）→ 把 script.json 结构注入 SCRIPT 槽并**回读自证**（写入后重新提取解析、与 script.json 逐位核对）。**重跑安全**：之后每次改完 script.json 就重跑它——只换剧本区，引擎区与主题手改原样保留。

**（可选）视觉主题**：装配完成后可对 index.html 做一处小 edit（★槽位3 色值：言情暖调用默认 `--vn-name: #e8c88f` 鎏金即成立；古风墨色可换 `#d4c5a9`）——没把握就不动，模板默认主题本就成立。这是全流程唯一允许 edit index.html 的例外；重跑 vn_assemble 不会冲掉它。

## 8. Schema 浓缩卡（vn-stage 接口契约；真源=模板头注释，本卡=常用位速查）

```
{
  "meta": {
    "title": "作品名", "slug": "<slug>", "version": 1,
    "locale": "zh",
    "freechatPlan": ["s03", "s07", "s11"],
    "stats": { "aff_<charId>": { "label": "名·好感", "init": 0, "min": -20, "max": 100, "visible": true } },
    "endings": [ { "id": "end_true", "title": "结局名", "scene": "e01",
                   "tagline": "结局卡收束语一行（可选）", "lockedHint": "收集册钩子文案（可选）" } ]
  },
  "characters": {
    "<charId>": { "name": "名", "persona": "完整人设段（freechat 的 LLM 吃它）",
                  "style": "台词风格一句话", "fcTone": "口吻纪律（可选，freechat 注入）",
                  "sprites": { "neutral": "cast/<id>-neutral.png", "smile": "cast/<id>-smile.png" } }
  },
  "scenes": {
    "s01": {
      "bg": "bg/xx.png",
      "sprites": [ { "char": "<charId>", "mood": "neutral", "pos": "center" } ],
      "lines": [ { "who": "<charId>", "mood": "smile", "text": "台词。" },
                 { "who": "", "text": "旁白（who 空串）。" } ],
      "freechat": { "char": "<charId>", "max": 3,
                    "note": "此刻锚点+防剧透底线（可选，强烈建议写）" },
      "choices": [ { "label": "选项文案", "ops": { "aff_<charId>": 5 }, "flags": ["某flag"], "goto": "s02" },
                   { "label": "条件项", "cond": { "all": [ { "stat": "aff_<charId>", "gte": 20 } ] }, "ops": {}, "goto": "s03" } ],
      "next": "s02"
    },
    "r01": { "endingRouter": [ { "cond": {...}, "goto": "end_true" }, { "goto": "end_normal" } ] }
  },
  "start": "s01"
}
```

写剧本时必守的语义要点（引擎已逐字实现，写错的形态 lint 会抓）：

- **`meta.locale` 按剧本语言如实写**（`"zh"`/`"en"`，缺省=zh）——引擎的标题屏/收集册/存档面板/搭话话术整层 UI 与 freechat 的回复语言钉子都按它分轨。英文书漏写=英文作品顶着中文按钮、角色用中文回话（英文书试转实锤的第一屏硬伤）；vn_lint 会按正文语言对账 warn 点名。
- **主好感轴必须写 `"visible": true`**——visible 缺省=false=HUD 不显示：galgame 唯一反馈轴对玩家全程黑箱，选了半天不知道涨没涨（三闸全绿也拦不住的产品残废，男频试转实锤）。vn_lint 对「全剧本零 visible:true」warn 点名；刻意全隐藏数值的作品给每个轴显式写 `"visible": false` 亮明意图。
- **画外音/电话音/系统音不发明 speaker id**——who 写空串走旁白轨，需要「画外感」就在 text 里加「（画外）」前缀；禁止杜撰 `<id>_off` 这类未注册 who（lint error 白烧一轮自纠）。天书/系统/命运之声类抽象存在**不建 characters 条目**（它们不该有立绘，建了必然吃「整剧本零上台」warn）。
- **goto 双寻址**：先查场景 id，再查结局 id（`meta.endings[].id`）——`"goto": "end_true"` 合法，直接跳该结局的 scene。
- **结局场景必须终态**（无 choices/next/router）；router 场景不得再有 choices/next；**router 末条必须无 cond**（恒真兜底，否则存在无结局死路）。
- **每个选择点至少 1 个无 cond 的恒可见选项**（条件全不满足时选项组整体隐藏=坠落死路）。
- **ops 单键 |delta|≤15**（引擎硬顶）；键必须在 meta.stats 注册；freechat 只能动 `aff_<charId>` 约定键且 ±3。
- cond 叶子形态只有四种：`{"stat","gte"}` / `{"stat","lte"}`（同叶共存=区间）/ `{"flag"}` / `{"notFlag"}`；容器 `{"all":[…]}`/`{"any":[…]}` 可嵌套。flags 只增不减。
- sprites 最多 3 位，pos ∈ center/left/right；mood 必须在该角色 sprites 键集里。
- **美术路径全部相对 `assets/play/art/`**（`"bg/x.png"` 实际=assets/play/art/bg/x.png）；缺图=引擎降级占位（渐变底/剪影卡），不发 404——纯文字档路径照写，作品照玩，后补图零改剧本。
- freechat `note` 写「此刻」锚点+「绝不说破 / 绝不提」防线（引擎自动追加剧透纪律段）；`max` 正数=次数上限，0=显式关闸，缺省=1。
- **`meta.freechatPlan`**=蓝图布点表的场景 id 数组（§5-5 逐字抄，引擎不消费=纯对账位）——vn_lint 按它对账实际布点，声明未兑现/计划外布点/场景 id 漂移都会 warn 点名，收到就补齐或改声明。**「全剧本零 freechat 且没写 freechatPlan」也会被 warn 点名**（v31 实锤形态：蓝图声明了 3 处、产物两头全空=对账防线整个被绕过）——布点是本产品差异化本体，别丢；真要做纯选项作品就显式写 `"freechatPlan": []` 亮明意图。

## 9. 言情改编语法卡（工序管「怎么做」，本卡管「怎么做得像样」）

**名场面五型与场景化公式**（每个名场面拆成 2-4 个场景：铺垫 → 张力峰 → 选项 → 分岔余韵）：

| 型 | 张力来源 | 选项公式 |
|---|---|---|
| 误会型 | 信息差（TA 看到了/听说了不完整的事实） | 戳破 / 将错就错 / 先按下不表 |
| 拉扯型 | 进退边界（靠近一步还是退半步） | 进一步（高风险高好感）/ 退半步（安全但留遗憾钩） |
| 危机型 | 外部压力（家族/情敌/规矩压下来） | 挡在前面 / 各自周全 / 借力打力 |
| 告白型 | 时机（这句话现在说还是永远不说） | 接住 / 岔开 / 反问 |
| 和好型 | 台阶（谁先递、递不递） | 递台阶 / 等 TA 递 / 假装没吵过 |

**穿书/重生书的双模式**（本品类杀手场景）：正文 `@options` 块的 `picked="…"` 标注了原线——把它做成显式对照：「沿原线」选项（低风险，走向已知）vs「走岔路」选项（原创演绎）。选项 label 可以轻点一句「原著里她选了这条」——玩家的核心 fantasy 就是「这次我自己选」。

**拉扯手感三条**（言情张力的既有技法，浓缩自拉扯十二式）：温度可逆——好感不许一路单调涨，中段至少一处「甜后回落」场景（别扭/误会回撤）；口是心非双轨——台词嘴硬、旁白行泄露真心（「嘴上让你走，指尖却勾住你袖口」拆成两行）;破例独占——好感高位解锁的条件选项写成「只对你破例」的具体事（唤小名/让出半张伞），不写抽象的「关系更近了」。

**好感轴映射纪律（数值预算）**：`aff_<charId>` 初值从原著当前关系态推导，**蓝图里向用户念一遍推导依据**（「第 K 章他刚为你挡了雨但嘴上否认，初值定 15」）；选项 delta ±3~±8 为主（言情的心动是小步累积），±12~±15 只给名场面级抉择；**结局门槛从可达性倒推，动笔前先把预算算一遍**：门槛 ≤ 初值 + 全甜路线（单条路径，不是全选项加总）选项 ops 之和——全甜打满应「恰好撞线」隐藏结局门槛（窄区间设计，太松=结局廉价、太紧=假承诺）；freechat 的 ±3×次数是模型建议值不保证给满、玩家也可能不搭话，**不许把它算进门槛预算**（只当富余体验）。vn_lint 的数值可达性检查是这条纪律的机器闸：门槛 > 可达上界=error 当场拦（v31《红楼梦·选回》「≥25 解锁、满分 19」实锤形态）、只有靠 freechat 满额才够得着=warn 点名——**它只管数学不管戏剧**，撞线的手感仍要你自己算。**门槛可达性要验两头**：甜/隐藏结局验「全甜路线够得着」（上面那条），失败/低好感结局（lte 门或低位 gte 门）还要验「摆烂路线真的到得了」——心算口径：初值 + 每个选择点**最负**选项的 ops 之和，应显著低于失败门槛（留 ≥3 分余量）；随机玩家永远撞不见的失败结局=收集册第二格假承诺（历史严肃向试转实锤：init 10 + 选项多为正 → 「信任 <25」断义线 5000 局 0 命中，第二结局形同虚设）。vn_lint 的蒙特卡洛对占比 <5% 的结局会 warn 点名，收到就二选一处置：刻意窄门（golden 已证可达的隐藏结局）如实说明；数值失衡就补负向选项供给或调门槛。两条实测踩过的坑：① **分幕写作中途改掉任何 ops 数值后，必须回头把蓝图的可达性验算重推一遍再复跑 vn_lint**（试点实锤：写作时把某选项的好感+3 改成纯氛围，蓝图验算没跟着更新，导致一条支线最高只能拿到门槛差 1 分——数值死门就是这么来的）；② **cond 解锁的特殊选项收益不得低于同选择点的普通项**（玩家花了前置 flag 换来的选项拿更少分=负奖励）。

**台词红线（提炼纪律的 VN 操作化）**：原著台词逐字不进 lines[]——改写至少动语序/用词/视角其一；名台词可「化用意象」不可照抄。绿/黄档允许 ≤500 字引语级样例但**只进 persona 的文风描述段**不进台词；红档零引语，persona 里只写风格描述（「短句为主、爱用反问、被戳中心事先凶后软」）。

**freechat 布点纪律**：每部 3-5 处，布在**情绪余韵场景**（名场面后一拍——刚吵完/刚心动完最有话聊），不布在抉择点上（抉择前搭话会泄题）。每处 note 必写两件：「此刻」锚点（TA 刚经历了什么、情绪状态）+ 防剧透底线（「绝不说破 X」——X=该支线玩家还没看到的信息）。布点定稿写进蓝图布点表（§5-5）并抄进 `meta.freechatPlan`——freechat 是本产品对所有「预制互动小说」的差异化本体，布点丢了=白做一半，lint 对账就是防这个。

**结局写作**：2-3 个结局全部是已读素材的原创演绎；**结局正文引用的每个具体事件过一遍「全路径必经性」自查**——甜结局提到「你递伞那天」，而递伞只在 A 支线发生 → 走 B 支线到达该结局的玩家没见过这件事（幽灵记忆，本品类最高发缺陷；lint 的 REVIEW 清单会机械提示，收到逐条处置：改写成全路径公共事实 / 把出处挪进必经场景 / 给结局加只能从该支线到达的门）。每结局配 tagline（一行收束语）+ lockedHint（收集册钩子，如「？？？（她好像在等一个人）」）。

## 10. 机器闸自纠（≤3 轮硬顶，不过就停下如实报告）

```
① exec: python /foreverse/scripts/vn_lint.py /workspace/<slug>        ← 只读免确认
② exec: python /foreverse/scripts/validate_play.py /workspace/<slug>  ← 只读免确认
```

- 次序固定：先 vn_lint（剧本语义：JSON 语法/goto 死链/结局可达/**数值可达（门槛 > 全路径可达上界 = 死门 error，v31 形态）**/ops 越界/坠落死路/**script.json↔index.html 装配一致**——validate 不解析 SCRIPT，抓不到这些）再 validate（包级：manifest/桥白名单/资产死链/垫片残留）。
- **修复循环 = edit script.json → 重跑 vn_assemble → 复跑双闸**。改了 script.json 不重新装配会被 vn_lint 的一致性检查当场拦下（入库的是 index.html 里的内嵌剧本，不是 script.json）。两者都按行级中文报错，**双 0 errors 才进入库**。lint 的 `[WARN]` 逐条读（多数是漏写阈值/冗余 next 类真提示）；`[REVIEW]` 是幽灵记忆复核清单，按 §9 结局写作的三种处置逐条过。
- **自纠 ≤3 轮**：3 轮后仍有 error 就停下，如实告诉用户卡在哪条、你打算怎么改、要不要继续（继续=新的调用成本）。不许无限烧。
- validate 抓不到的必死面自查（play-author §5 同源）：`fv.ready()` 在场（模板自带，装配器从不碰引擎区）；JS 引用的元素 id 都存在（本工序只产 SCRIPT 数据不动引擎区，天然安全——**引擎区一个字都别改**）。
- **两个高频跑偏（设备试点实锤，都别做）**：① 不要自写 python 脚本**校验/生成/合并** script.json / index.html——写剧本=write --append、修剧本=edit、装配=vn_assemble（落盘即回读自证）、校验=vn_lint，全链没有自写脚本的位置；自写脚本只会连环弹强确认卡白耗轮次白花钱（英文书试转的 14 步自写生成器实测多烧 ~40% 调用）；② exec 不是 shell——`a && b` / `a | head` / `2>/dev/null` 这类链式/管道/重定向形态会被直接拒绝，**一次一条命令**（别把「修复 → 装配 → lint」串在一条命令里）。

## 11. 美术三档（§2 已报价，此处是执行）

**素材库优先工序（报价前必查；miss 才生图）**——凡要生成背景/BGM/SFX/路人立绘之前，先查已导入的官方素材包：

1. `read /foreverse/assets/asset-library` —— 列出已导入哪些题材包（空目录=一个都没装）；
2. `read /foreverse/assets/asset-library/<packSlug>/INDEX.json` —— 按 `tags` 检索（题材/kind/时段/氛围/性别/气质），`desc` 是英文原始描述可辅助判断；
3. 命中项报「零成本复用」：背景/BGM/SFX/路人位直接 `fs.py copy --from /foreverse/assets/asset-library/<packSlug>/<file> --to /workspace/<slug>/assets/play/art/…` 进作品目录（字节流零 token），报价单只列 miss 项的生图费用；
4. 全 miss 且社区有对口题材包时，先问用户要不要**免费**下载素材包再动工（`community.py download` 一次确认；素材包不占下载额度），装好再按命中后的口径报价；
5. **主角/对手戏主立绘不从素材库直接配**（气质检索到不了「原著脸」，撞脸=OOC 级伤害）：默认仍生成，但从素材库挑一张气质/构图最近的立绘当 `generate_image --ref` 的 i2i 风格锚（画风与库存背景同源、构图合格率高、省重摇）；用户明说「随便配一张能看的」才允许直接复用素材库立绘当主角；
6. **音频只有素材库一条供给路**（官方渠道无音乐生成模型）：BGM/SFX 一律从包里选，INDEX 的 `desc` 就是选曲说明，拿不准列 2-3 首让用户挑。

- **A 纯文字**：零步骤。SCRIPT 里的 bg/sprites 路径照写（规范命名 `bg/s01.png`、`cast/<id>-neutral.png`），引擎降级渲染，后续升级 B/C 档零改剧本。**A 档也先跑素材库优先工序**——命中背景+BGM 就白拿一档观感（背景真图+配乐的完整 VN 形态，一分钱生图不花）。
- **B 封面+立绘**：先查 `cast.json` 有无现成立绘（`portrait`/`sprites` 字段）——有则 `fs.py copy` 进 `/workspace/<slug>/assets/play/art/cast/` 零成本；没有才 `generate_image` ×2（每张弹付费确认属正常）。生图 prompt 纪律：立绘写死 "VERTICAL portrait-orientation, full body, plain background"+**睁眼守卫**（笑系表情带 "eyes wide open"）；封面**永不写 "book cover"**（乱码文字诱因），写 "textless key-art"；背景**永不写 "phone wallpaper"/数字比例**（假状态栏伪影诱因）。
- **C 全套 ≈15 张（一次授权整批跑，2026-07-23 拍板）**：
  - 用户指定自己的/社区导入图片提示词时，先读 `prompt-template-user` 技能，用 `templates.py list --kind image → show` 看完全文，再给本批每个 `generate_image` 加同一 `--template <templateId>`；planner 模板不能直接传。把模板选择写进动工前清单，模板变化被拒时先停下重新 show，不得静默降级。
  1. 动工前定稿全部生图清单（哪张封面/哪些差分/哪些背景，含每张 prompt 要点），向用户复述「N 张 × ≈1080 ≈ 总价 credits」——这就是用户即将授权的全部内容，开跑后不许再加张数；
  2. 发起第一张 `generate_image` 前提醒用户：「这张的付费确认卡上点『后续全部允许』，剩下的图就不再逐张确认（会话会切成自动审批模式，之后可在输入条的模式按钮改回）；想逐张把关就每张点应用」——『后续全部允许』是系统确认卡自带的按钮，如实转述即可，不是你伪造的交互；
  3. 生成顺序按「中断了也最值钱」排：主角 neutral 立绘先行（表情差分要拿它当 `--ref` 锚）→ 封面 → 表情差分（`generate_image --ref` 带 neutral 原图逐表情改写，i2i 保脸）→ 背景；
  4. 每张落盘即保留。用户中途喊停/点停止=**正常出口不是事故**：已生成的图都在（已付费产物，绝不删），SCRIPT 零改动（缺图自动走降级渲染），之后想补随时从缺的那张继续；
  5. 批量期间不要输出闲聊文本结束回合——一口气串行到完成或用户叫停。

## 12. 入库与溯源（source.json 是硬步骤，漏写=产物零档位标记）

```
① write /workspace/<slug>/_play/source.json     ← 入库前 staged（M192 起首选：随导入原子带进 world）
② exec: python /foreverse/scripts/import_play.py /workspace/<slug>     ← 普通确认门
③ 从 stdout 拿 world_id= 行（收尾 [[book:<world_id>|作品名]] 用）
```

忘了 staged / 入库后要修正档位时的兜底：`write /foreverse/assets/worlds/<world_id>/_play/source.json`（落点等价，别两处写不同内容）。

source.json 字段名逐字照抄（camelCase，发布链机器读取，自创同义键=等于没写；用不上的留空串不删键）：

```json
{
  "schemaVersion": 1,
  "sourceType": "novel",
  "sourceWorldId": "<原书 worldId>",
  "sourceLibraryId": "",
  "sourceBranch": "main",
  "chapterRange": [K, K+7],
  "rights": "red",
  "rightsBasis": "imported- 前缀本地导入书，无社区溯源边车",
  "boundaries": "",
  "sourceTitle": "",
  "communityPackId": "",
  "communityAuthorName": "",
  "convertedAtMs": <exec date +%s%3N 的输出，原样粘贴>
}
```

**`convertedAtMs` 必须先 `exec date +%s%3N` 拿真值再写文件**——禁止手写「看起来像毫秒时间戳」的 13 位数（该字段编数/抄旧值事故已五连发；import 闸对 2026 前的值当场打回，每次=白烧一轮自纠）。本文示例里该字段全是占位符，**没有可抄的数**。`rights`/`rightsBasis` 按 §3 定档结果如实填；黄档把源的 packId/authorName 抄进对应键、boundaries 声明原文抄进 `boundaries`、**源作品标题抄进 `sourceTitle`**（发布后详情页「改编自《XX》」具名溯源行的数据源；漏填时服务端会按 `communityPackId` 查库补，但源作品已删就补不回来——如实抄最稳）。schema 真源在 play-author §10.2，两边键名保持同步。**rights 键是发布链的分级闸判据**（green/yellow 放行、red 拒收，App 预检与 server 主闸双侧同判据）——它决定这个作品将来能不能发布，必须如实填写。写完不需要 validate（source.json 不在作品包校验面内）。

**黄档（社区下载书，含官方小说）的抄录映射**——三个溯源键逐一从源书 world 目录的 `community_source.json` 抄（该边车 §3 定档时已读过）：`packId`→`communityPackId`、`title`→`sourceTitle`、`authorName`→`communityAuthorName`、`boundaries`→`boundaries`。填好的形态：

## 13. 诚实收尾（五件必说，一件不许漏）

1. **怎么玩**：「书架上找《作品名》打开玩（[[book:<world_id>|作品名]]）。名场面重演+你自己选走向，有 N 个结局可收集；场景里出现搭话入口时可以直接和 TA 聊几句」。
2. **费用语义**：「主线推进零调用——断网照玩；只有搭话（freechat）每次走你的模型计费」。绝不承诺全免费，绝不报搭话的具体积分数。
3. **定位诚实**（原话可用）：「这是 AI 根据你读过的章节改编的同人试玩，不是官方精品——名场面还原度和结局逻辑可能有毛边，**玩到穿帮的地方可以让我修**」。
4. **边界**：按 §3 档位如实交代发布语义——红档/禁二创=锁本地声明；绿/黄档=「想分享的话，社区页 → 顶部『发布』→ 类型选『文游』就能发」；补一句「游戏里的台词是 AI 重写的演绎，不是原文」。
5. **分流**：「想要原文原样演出来的感受，阅读器里的 VN 剧场是另一条路（不花钱、跟着阅读进度走）」。

用户反馈「结局太容易/某段 OOC/选项没意思」时的定点手术位：结局门槛→endingRouter 的 cond 阈值；OOC→该场景 lines 改写+persona 补一句；选项→按 §9 五型公式重写该选择点。改完重跑 §10 双闸再确认。
